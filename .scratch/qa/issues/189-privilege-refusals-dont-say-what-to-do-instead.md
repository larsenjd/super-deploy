## Agent Brief

**Category:** enhancement
**Summary:** Each privilege refusal ends with what to do instead and points to the README's "Permissions" section.

**Current behavior:**
`GRANT is not supported: privileges and row-level security are set up on targets outside super-deploy [unsupported-object]`, and the same for `REVOKE`, `ALTER DEFAULT PRIVILEGES`, policies, RLS flags, roles and ownership. They say where privileges belong but not what to do, and `ALTER DEFAULT PRIVILEGES` is refused with no hint that it is the README's recommended statement, run on the target.

**Desired behavior:**
Keep each message's first part (and the spec's required wording); add a next step:
- grants, revokes, policies and RLS flags: remove it from the file and run it on each target instead; see the README, "Permissions".
- `ALTER DEFAULT PRIVILEGES`: run it on each target as the deploy role, where it grants what every deployment creates; see the README, "Permissions".
- roles and role membership: create and grant roles on each target, outside super-deploy; see the README, "Permissions".
- `OWNER TO`, `REASSIGN OWNED`, `DROP OWNED`: remove it; the deploy role owns everything it creates.
- `SECURITY DEFINER` keeps its message, plus the same README pointer.

**Key interfaces:**
- The privilege refusal reasons (`privilegeRefusal`), shared by both rule sets. Rule id unchanged (`unsupported-object`).

**Acceptance criteria:**
- [ ] Each refused privilege statement's message, in the desired schema and in a deploy-time script, ends with its next step and the README pointer (unit seam; assert the pointer and the next step, not the whole text).
- [ ] The `ALTER DEFAULT PRIVILEGES` message says to run it on the target as the deploy role.
- [ ] The messages still say privileges and row-level security are set up on targets outside super-deploy.
- [ ] The README's "Refused" list mentions nothing that contradicts the new text.

**Out of scope:**
