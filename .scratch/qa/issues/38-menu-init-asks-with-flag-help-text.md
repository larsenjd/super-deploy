## Agent Brief

**Category:** enhancement
**Summary:** The menu asks options with a question written for the menu, not the flag's help text, starting with `init --adopt`.

**Current behavior:**
When a menu command needs an option, the menu uses the option's `--help` description as the question. For `init` in a project with no migrations, the question reads "Instead, in an initialised project with no migrations yet: turn this target's managed schema into the desired schema and migration 1, recorded on it as marked". The menu's summary of `init` says "in an empty project", meaning an initialised project with no migrations.

**Desired behavior:**
- An option definition can carry an optional menu question. The menu uses it when present and falls back to the description otherwise.
- `init`'s adopt option has a question that stands on its own, e.g. "Adopt which target's existing database as migration 1?", optionally with a short hint on what adoption does, in plain words (no "recorded on it as marked").
- The menu summary of `init` says "an initialised project with no migrations yet" (or equivalent) instead of "an empty project".
- `--help` output is unchanged.

**Key interfaces:**
- The option definition type in the CLI's command definitions (`CommandDefinition` options): a new optional field for the menu question.
- The menu's option prompt (`askOption`).

**Acceptance criteria:**
- [ ] Choosing `init` from the menu in a project with no migrations shows the new question, not text starting with "Instead," (pseudo-terminal seam, `chooseMenuItem`).
- [ ] `init --help` still shows the existing `--adopt` description.
- [ ] Options without a menu question are asked exactly as before.
- [ ] The menu's description of `init` no longer says "empty project".

**Out of scope:**
- Whether to pre-select a target (needs a decision, above).
- Rewording other options' questions, beyond adding the field.
