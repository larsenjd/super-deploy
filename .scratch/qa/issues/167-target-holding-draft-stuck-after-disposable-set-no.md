# 167: A target holding a deployed draft can be flagged not disposable without warning, and then "reset it with rebuild" refuses

**Status:** resolved
**Category:** enhancement
**Severity:** low
**Area:** disp
**Round:** 2

## What I did
Disposable target `qa` at migration 4.
```sh
pnpm exec super-deploy deploy-draft --target qa              # YES
pnpm exec super-deploy disposable --target qa --set no       # YES
pnpm exec super-deploy status --target qa
pnpm exec super-deploy rebuild --target qa --to 4
```

## Expected
The `disposable --set no` confirmation warns that the target holds a deployed draft and that `deploy` will refuse it until it is flagged disposable again and rebuilt. Or status's advice accounts for the flag.

## Actual
The confirmation shows the draft, but only says rebuild will refuse:
```
│  Deployed draft: add-tags (attempt #32)         │
│  deploy-draft and rebuild will then refuse it   │
```
Then status and deploy point to a command that refuses:
```
Deploy would refuse:
  the target holds draft add-tags (...), not a finalized migration: reset it with rebuild --to 4
...
Error: rebuild only runs on disposable targets, and target qa is not disposable (flag it with disposable --target qa --set yes if it is safe to wipe): nothing changed
```
The target can't be deployed until someone flags it disposable again, which is the opposite of what the person who flagged it "not disposable" wanted.

## Notes
Each message alone is fair. Following them gets out in two hops. Possible fixes: refuse `--set no` while a draft is deployed, or warn in the prompt; or have status say "flag it disposable again, then rebuild --to 4" when the target isn't disposable.

## Agent Brief

**Category:** enhancement
**Summary:** When a target holding a deployed draft is flagged not disposable, the confirmation says what that leaves, and the "reset it with rebuild" advice says to flag it disposable first.

**Current behavior:**
`disposable --set no` on a target holding a deployed draft gives no warning. Afterwards `status`, `deploy` and `mark` advise `rebuild --to N`, which refuses because the target isn't disposable.

**Desired behavior:**
- The `disposable --set no` confirmation, when the target holds a deployed draft, adds a line saying that `deploy` refuses the target until `rebuild` resets it, and that `rebuild` will then first need it flagged disposable again. It still goes ahead on YES: flagging a target not disposable is the safe direction and isn't refused.
- On a target that isn't disposable, the held-draft advice everywhere it appears (`status`'s "Deploy would refuse", `deploy`'s pre-flight refusal, `mark`'s `HistoryMismatchError`) reads e.g. `flag it disposable again (disposable --target qa --set yes), then reset it with rebuild --to 5`. On a disposable target it reads as today.

**Key interfaces:**
- `disposable`'s guarded `check()` details (it already gets the target view, with `draft`).
- `describeHeldDraft` and its callers: they need the disposable flag (`readTargetSettings`).

**Acceptance criteria:**
- [ ] Pseudo-terminal: `disposable --set no` on a target holding a deployed draft shows the extra line; on a target without one, the confirmation is as today.
- [ ] `status` on a non-disposable target holding a draft advises flagging it disposable, then `rebuild --to N`. On a disposable one, the advice is unchanged.
- [ ] `deploy`'s pre-flight refusal on the non-disposable target carries the same advice.

**Out of scope:**
- Refusing `--set no` while a draft is deployed.
- A draft deployed before any migration (164, the `rebuild --to N` placeholder).
