# 18: README doesn't say which PostgreSQL objects the desired schema supports; common ones (enums, sequences, extensions) are refused with "not supported in V1"

**Status:** ready-for-agent
**Category:** enhancement
**Severity:** medium
**Area:** newproj

## What I did
Added an enum to a working project's desired schema:
```sql
create type payment_state as enum ('pending', 'settled');
```
```sh
pnpm exec super-deploy draft --name "payment state"
```
Then probed other common object kinds one file at a time, each with
`pnpm exec super-deploy draft --name probe`.

## Expected
The README (step 1 of Getting started: "Describe the schema you want as
`CREATE` statements") says what may go in the desired schema and what isn't
supported, so I can decide whether the tool fits *before* adopting it.

## Actual
Refused, each with `[unsupported-object]`:
```
Enums are not supported in V1: use a lookup table with a foreign key, or a CHECK constraint
Standalone sequences are not supported in V1: use an identity column (`bigint generated always as identity`)
Extensions other than plpgsql are not supported in V1          (create extension pgcrypto / btree_gist)
Partitioned tables are not supported in V1
Unlogged tables are not supported in V1
Range types are not supported in V1
Custom collations are not supported in V1
Custom aggregates are not supported in V1
CREATE STATISTICS is not supported in V1
Rules are not supported in V1
Event triggers are not supported in V1
Text-search configurations are not supported in V1 (nor their dictionaries, parsers and templates)
CREATE SCHEMA is not allowed in the desired schema: super-deploy manages one schema and creates it itself
```
Accepted: materialized views, procedures, stored generated columns,
expression indexes, RLS policies.

None of this is in the README. The README's "Adopting an existing database"
section says only that adoption lists "anything super-deploy doesn't
support", without saying what that is.

## Notes
- "V1" isn't explained anywhere (`--version` prints `0.0.0`). Say "not
  supported yet" or explain the version scheme.
- The enum and sequence messages suggest alternatives, which helps; most
  others don't.
- Enums and extensions (`pgcrypto`, `citext`, `pg_trgm`) are common enough
  that their absence belongs near the top of the README.

## Agent Brief

**Category:** enhancement
**Summary:** Add a "What the desired schema supports" section to the template README, so users can judge fit before adopting.

**Current behavior:**
The template README says to "describe the schema you want as CREATE statements", but never says what may go in the desired schema. Users find the refused object kinds one `draft` at a time, through `[unsupported-object]` errors. That includes common ones: enums, standalone sequences, `serial`, extensions other than plpgsql, and partitioned tables. They likewise find out by trial that constraints must be named.

**Desired behavior:**
The template README has a section, linked from Getting started step 1 and from "Adopting an existing database", that lists:
- what the desired schema supports, in one short list;
- what it refuses, grouped as REFINEMENTS.md groups it, each with the suggested alternative where the refusal message has one;
- the authoring rules a user will hit: indexes and constraints must be named, except primary keys and NOT NULL, with the reason; no `IF NOT EXISTS` or `OR REPLACE`; one managed schema, with no `CREATE SCHEMA`.

Common refusals come first: enums, extensions, sequences and `serial`.

**Key interfaces:**
- The template README.
- Sources of truth: REFINEMENTS.md's refused-object sections, the rule catalogue (rule ids and categories), and the desired-schema rule messages. The README must agree with what the rules actually refuse.

**Acceptance criteria:**
- [ ] Every object kind the `unsupported-object` rule refuses is listed in the README section.
- [ ] Spot check at the API or SQL-analysis seam: an enum, a standalone sequence, `serial`, `create extension pgcrypto` and an unnamed check constraint are each refused, and each is in the README.
- [ ] The README states the constraint-naming rule and its exceptions.
- [ ] The template's precommit still passes.

**Out of scope:**
- Supporting any of these objects.
- Rewording "V1" in messages (a human decision, noted on issue 35).
- Showing all violations at once (issue 02).
