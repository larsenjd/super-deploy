# 144: An interrupt that arrives after deploy or finalize has finished prints success, then "Interrupted" and exit 130

**Status:** resolved
**Category:** bug
**Severity:** low
**Area:** fail
**Round:** 2

## What I did
**deploy to dev**, with SIGINT sent as soon as the success line appears (while the CLI stops its embedded servers, about 240 ms):
```sh
setsid pnpm exec super-deploy deploy --target dev > t.out 2> t.err & P=$!
while ! grep -q Deployed t.out 2>/dev/null; do sleep 0.01; done
kill -INT -- -$P; wait $P; echo "exit=$?"; cat t.out t.err
pnpm exec super-deploy status --target dev
```
**finalize** of a draft whose rehearsal takes about 6.5 s, with SIGINT to the process group at 6.6 s.

## Expected
The work had finished (committed or written), so the exit code is 0, or at least the message makes clear the work is done and only the cleanup was cut short.

## Actual
deploy:
```
exit=130
Deployed 1 migration to dev: 00013-c2
Interrupted by SIGINT: cleaning up before exiting (interrupt again to exit at once)
```
`status --target dev` shows `#3 deploy succeeded migration 13`.

finalize:
```
exit=130
Finalized migration 00011-events in data-model/migrations/00011-events
Interrupted by SIGINT: cleaning up before exiting (interrupt again to exit at once)
```
`validate` passes and the migration is complete.

## Notes
A script like `deploy && notify-success`, or a CI step, treats this as a failed deploy although it committed. Round 2 made interrupted deploys exit with the interruption's code. That is right while the deployment runs, but once it has committed, the exit code should report success.

### Triage, 2026-10-21

**Verification:** CONFIRMED with `deploy --target dev`: SIGINT to the group as soon as `Deployed 22 migrations to dev` appeared gave exit 130 and the interruption notice. `status` shows `#1 deploy succeeded migrations 1-22`. finalize wasn't rerun; it takes the same path.

**Root cause:** the command prints its result and returns, then `runCommand` (`cli/run.ts`) closes the project, which stops the embedded servers. A signal during that close sets the interruption's exit code (`watchInterruptions` in `cli/process.ts`, which also sets `process.exitCode` at once), and `cli.ts` exits with it whatever the command's own code was. Round 1's 40 made the interruption code win so that a cancelled deploy can't exit 0; it didn't consider a command that had already finished.

## Agent Brief

**Category:** bug
**Summary:** An interruption that arrives after a command has finished doesn't change its exit code.

**Current behavior:**
If SIGINT, SIGTERM or SIGHUP arrives after a command has done its work and printed its result, while the CLI stops its embedded servers, the CLI prints `Interrupted by SIGINT: cleaning up before exiting` and exits 130 (or 143, 129). A deploy that committed looks like a failure to `deploy && …` and to CI.

**Desired behavior:**
- Once the command's outcome is settled (its function returned or threw), a later interruption doesn't change the exit code: 0 after success, 1 after a failure.
- The notice for such an interruption says the command had already finished, e.g. `Interrupted by SIGINT after deploy finished: stopping the embedded servers`.
- A second signal still exits at once, with the command's own exit code.
- An interruption while the command is still running behaves as today (130, 143, 129).

**Key interfaces:**
- `watchInterruptions` / `ProcessInterruptions` and the exit code `cli.ts` picks.
- `runCommand`, which knows when the command's outcome is settled (before `settleCleanups` and `project.close()`).

**Acceptance criteria:**
- [ ] CLI seam: a deploy whose project closing is slowed down (e.g. its embedded server owned by the child), signalled with SIGINT after the result line, exits 0, and `status` shows the attempt succeeded.
- [ ] The same signal during the deploy transaction still exits 130 with the attempt abandoned (the existing interruption tests pass).
- [ ] A command that failed before the signal exits 1.

**Out of scope:**
- Repeated signals from a terminal plus a wrapper (141).
- What an interrupted deploy prints (110).
