# 105: In a subfolder of an existing Git repo, the pre-commit hook is silently not installed

**Status:** ready-for-agent
**Category:** bug
**Severity:** medium
**Area:** newproj
**Round:** 2

## What I did
A common layout: the schema project lives in a folder of an application's repo.
```sh
mkdir -p monorepo/db && cd monorepo && git init
cd db && node <cli> init
pnpm install
cd .. && echo "create table t (id int primary key, x serial);" > db/data-model/desired-schema/t.sql
git add -A && git commit -m test
```

## Expected
`pnpm install` installs the hook, as the README's "Getting started" says, or says clearly that it couldn't and
what to do. The commit is then blocked: `serial` is refused.

## Actual
`init` notices the repo: its "Next:" line drops `git init`:
```
Initialised a super-deploy project in /tmp/sd-qa2/newproj/monorepo/db
Next: pnpm install, add CREATE statements under data-model/desired-schema/, then run draft
```
`pnpm install` prints, among its normal output:
```
. prepare$ husky
. prepare: .git can't be found
. prepare: Done
```
No hook is installed (`git config core.hooksPath` is unset), and the commit with a refused statement succeeds.

## Notes
- Easy to miss: the install reports success.
- The README doesn't say that the project has to be the root of its Git repository, or how to set up the hook
  otherwise (for example a hook at the repo root that runs `pnpm --dir db precommit`).
- Related: `init` in a folder that already has a `package.json` or `README.md` refuses with `Cannot initialise a project in
  ...: it already has README.md, package.json`, without saying to use an empty folder. So a subfolder is the natural
  choice for an existing app repo, which is the case above.

### Triage, 2026-10-21

**Verification:** CONFIRMED with the built CLI. I ran `git init` in `mono/`, then `init` in `mono/db` and `pnpm install`. `init` printed "Next: pnpm install, …", without `git init`. `pnpm install` printed `prepare: .git can't be found`, `git config core.hooksPath` is unset, and no hook is installed.

**Root cause:**
- The template's `prepare` script is plain `husky`, which only works when the package folder is the Git root. Run elsewhere, it prints a note and exits 0.
- `init`'s next-steps line (`cli/definitions.ts`, `insideGitWorkTree`) looks for `.git` in the folder *or any folder above it*. So it treats a subfolder of a repo like a repo root, and drops `git init` without saying the hook won't be installed.
- The README's Getting started assumes the project is the repo root.

**Not a design question:** installing the hook at the repo root automatically would overwrite an application repo's own hook setup (`core.hooksPath` holds one path). So the answer is to say so and document the recipe. Husky's documented form for a subfolder: `"prepare": "cd .. && husky db/.husky"`, with the hook doing `cd db` first.

## Agent Brief

**Category:** bug
**Summary:** When the project isn't at the root of its Git repository, `init` says the pre-commit hook won't be installed, and the README shows how to run `precommit` from the repo's own hook.

**Current behavior:**
`init` in a subfolder of a Git repository prints "Next: pnpm install, …" as if the hook will be installed. `pnpm install` reports success, and no hook runs, so commits with refused SQL go through. The README doesn't cover a project inside a larger repository.

**Desired behavior:**
- `init` distinguishes three cases:
  - not in a Git work tree (as today: `git init`, then `pnpm install`);
  - at the root of one (as today);
  - in a subfolder of one. Here the next steps still say `pnpm install`, plus one line: the project is inside the Git repository at `<repo root>`, so `pnpm install` won't install the pre-commit hook; see the README section.
- The README gains a short section for a project inside another repository. It says to run the project's `precommit` from the repository's hook, e.g. `pnpm --dir <folder> precommit` in a hook at the root. It shows Husky's subfolder form (`prepare: cd .. && husky <folder>/.husky`, and `cd <folder>` at the top of the hook). It warns that a repository with its own hook setup should add the line to that setup instead.
- `init`'s refusal of a non-empty folder ("it already has README.md, package.json") adds that it needs an empty folder, e.g. a new subfolder.

**Key interfaces:**
- The `init` command's `CommandDefinition` result rendering and its git check (it needs the repo root, not just "a `.git` above").
- `InitConflictError`: message only.
- The template README's Getting started.

**Acceptance criteria:**
- [ ] CLI seam: `init` in a subfolder of a temp Git repository prints the hook line naming the repository root. `init` at a repo root and outside a repo print as today.
- [ ] CLI seam: `init` in a folder holding `package.json` refuses with a message that mentions an empty folder.
- [ ] The README section's recipe, followed in a temp repo with the project in a subfolder, makes a commit containing `serial` fail.
- [ ] The template's precommit still passes.

**Out of scope:**
