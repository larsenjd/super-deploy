# 63: rebuild fails with a bare "must be owner of extension citext" and no next step

**Status:** wontfix
**Category:** bug
**Severity:** medium
**Duplicate of:** 61
**Area:** disp

## What I did
Disposable target `sb2`, deploy role `disp_deploy` (owns the database, not a
superuser), migrations 1-5 deployed. An administrator installs an extension
into the managed schema:

```sql
-- as postgres (superuser)
create extension citext;
```

Then `pnpm exec super-deploy rebuild --target sb2 --to 5` at a terminal,
typing `YES`.

## Expected
Either rebuild checks what it can drop *before* asking for YES, or the error
names the object, says it is owned by `postgres`, says nothing changed, and
says what to do (drop it or change its owner, or ask the owner to), like the
README describes for admin-made grants ("fails without changing anything,
naming each such grant").

## Actual
The confirmation box doesn't mention the extension; after `YES`:

```
Error: must be owner of extension citext
```

With `--debug` it's a raw node-postgres error from `wipeManagedSchema`. The
attempt is recorded as `rebuild failed ... must be owner of extension
pgcrypto`. The transaction was rolled back (the target was unchanged), but
the message doesn't say so. After `drop extension citext` rebuild works.
Reproduced with `pgcrypto` and `citext`.

## Notes
Tables owned by other roles in `public` are dropped fine (the deploy role
owns `public` through `pg_database_owner`), so this seems to be specific to
objects like extensions where schema ownership isn't enough.
