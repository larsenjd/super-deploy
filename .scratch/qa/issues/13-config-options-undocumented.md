## What I did
Read the README to find out which schema super-deploy manages and how to use
`app` instead of `public`. The Permissions section talks about "the managed
schema" and uses `app` in its examples ("A managed schema other than `public`
needs this", "grant the deploy role `usage, create on schema app ...`"), and
mentions `externalSchemas` in `super-deploy.config.ts`, but never says how to
set any of them. The generated config only has `postgresVersion`, `rehearsal`
and `targets`.

Using TypeScript errors on a probe file I found that `SuperDeployConfig` has
`directory`, `externalSchemas`, `historySchema`, `managedSchema`,
`postgresVersion`, `rehearsal`, `targets`, and a target has `adapter`,
`lockTimeout`, `statementTimeout`.

## Expected
A config reference in the README (or commented examples in the generated
`super-deploy.config.ts`): the managed schema (default `public`?), the history
schema (I found `deployment_history` created on my target), `externalSchemas`,
and the per-target timeouts and their defaults.

## Actual
None of these are documented. A user who wants `app` has to guess. The README
even says unqualified desired-schema objects land in "the managed schema", and
`draft` writes `"public".` everywhere, with no hint that it's configurable.

## Notes
`lockTimeout`/`statementTimeout` matter for the lock warnings `rehearse` and
`finalize` print ("holding an ACCESS EXCLUSIVE lock that blocks every read and
write ... until the deployment commits"). The warning could mention them.
