# 39: No warning when a role is granted objects in a non-public managed schema but has no USAGE on it

**Status:** wontfix
**Category:** enhancement
**Severity:** low
**Area:** adopt

## What I did
In the adopted `shop` project (managed schema `app`), I added only an object grant for a new role:

```sql
-- data-model/desired-schema/grants.sql
grant select on app.refunds to adopt_auditor;
```
```sh
# (role created outside super-deploy, with CONNECT on the database)
pnpm exec super-deploy draft --name "auditor reads refunds"
pnpm exec super-deploy finalize
pnpm exec super-deploy deploy --target shop
```
Then, as `adopt_auditor`: `select count(*) from app.refunds`.

## Expected
The README does say a managed schema other than `public` needs `grant usage on schema app to ...` "or no role but the deploy role can reach its objects". A grant that can never take effect is easy to detect statically, so `draft`/`finalize` could warn: "adopt_auditor is granted SELECT on app.refunds but has no USAGE on schema app".

## Actual
Draft, finalize and deploy all succeed silently. The role then gets:

```
permission denied for schema app
```

### Triage, 2026-10-20

**Verification:** CONFIRMED-BY-CODE. No rule or warning connects object grants to schema `USAGE`. The desired-schema rules only limit schema grants to `USAGE` on the managed schema (`src/sql-analysis/desired-schema-rules.ts:590-616`). The README already documents the requirement ("A managed schema other than `public` needs this"). Caveat: `USAGE` can come through role membership or a grant to `PUBLIC` made outside super-deploy, which static analysis can't see. So a check can only warn, with false positives.

## Brief (ready-for-human)

**Category:** enhancement
**Summary:** Warn when the desired schema grants a role objects in a non-`public` managed schema but never grants it `USAGE` on the schema.

**Current behavior:**
`grant select on app.refunds to adopt_auditor` with no `grant usage on schema app to adopt_auditor` drafts, finalizes and deploys silently. The role then gets "permission denied for schema app".

**Desired behavior (once decided):**
A warning names the role, the object grants and the missing `grant usage on schema <managed> to <role>`. The managed schema `public` is exempt.

**Key interfaces:**
- The desired-schema analysis of grants (`analyseDesiredSchema` and its warnings).
- Whichever command surfaces the warning (`draft`, `finalize`, `validate`).

**Acceptance criteria (once decided):**
- [ ] An object grant without schema `USAGE` for the same role gives the warning in the chosen command.
- [ ] Adding the `USAGE` grant removes it.
- [ ] No warning when the managed schema is `public`.

**Out of scope:**
- Checking role membership on targets.
- Refusing the grant.

**Why not delegated:** a warning that can be wrong (membership, `PUBLIC`) needs a call on whether it's worth it and where it lives.
**Decision needed:**
- A `validate` and `draft` warning, with the text noting that membership-based `USAGE` makes it safe to ignore (recommended).
- No warning; rely on the README.

### Closed, 2026-10-20

Out of scope. ADR-0006 puts privileges, ownership and row-level security outside the system in V1 (`.scratch/super-deploy/issues/28-privileges-out-of-scope.md`). The desired schema no longer grants to any role.
