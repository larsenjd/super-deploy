### Triage, 2026-10-21

**Verification:** CONFIRMED. After `disposable --set yes` on my target, `status` listed `#2 disposable succeeded by jonathanl at ...`, with no direction.
- Root cause: the `attempts` table has no field for a command's argument. A `disposable` attempt has no migration range (`deploy/history.ts` header, "Layout version 1"), and `status`'s attempt line (`describeAttempt`, `cli/definitions.ts`) prints command, outcome and range only.

- Spec story 63 ("every deployment attempt recorded") and story 77 make this the only record of who made a target wipeable.

## Agent Brief

**Category:** enhancement
**Summary:** A `disposable` attempt records which way it set the flag, and `status` shows it.

**Current behavior:**
Each `disposable` run is recorded as `disposable succeeded` (or failed, or abandoned), with nothing saying whether it set the flag to yes or to no. Only the current value is visible, as "(disposable)" in `status`'s first line.

**Desired behavior:**
- The attempt row of every `disposable` run records the value it sets (yes or no), from the moment the attempt is opened, so failed and abandoned runs show it too.
- `status`'s recent attempts show it: `#5 disposable set yes succeeded by ...`, `#4 disposable set no succeeded by ...`.
- Other commands' attempt lines are unchanged.
- The history schema's documented layout (the header of the history module) lists the new field. The layout stays version 1, since it is unreleased.
- An attempt row without the value (made before this change) prints as today.

**Key interfaces:**
- The `attempts` table in the history schema (a new nullable column, or an equivalent).
- The attempt record type `status` reads (`AttemptRecord`) and the opening of the manual attempt (`withLockedTarget`/`runGuarded` with the command's argument).
- `status`'s attempt line.

**Acceptance criteria:**
- [ ] After `disposable --set yes`, then `--set no`, `status` shows `disposable set yes` and `disposable set no` on the two attempts. Pseudo-terminal seam for the guarded runs; reading the attempt rows may be at the API seam.
- [ ] A `disposable` run that fails after YES (e.g. the target changed while it waited) still records the value on its failed attempt.
- [ ] Attempt lines of `deploy`, `rebuild`, `mark` and `deploy-draft` are unchanged.

**Out of scope:**
- Recording other commands' arguments (`deploy-draft --with-seed` is already recorded on the deployed draft).
- Showing when the current flag was last set in `status`'s first line.
