# 55: Piping output to `head` prints "Output closed: cleaning up before exiting"

**Status:** ready-for-agent
**Category:** enhancement
**Severity:** low
**Area:** fail

## What I did
```sh
pnpm exec super-deploy status --target kill | head -1
```

## Expected
Quiet exit, as with other CLIs, or as `super-deploy --help | head -1` behaves.

## Actual
```
Target kill: 8 migrations recorded, 0 pending
Output closed: cleaning up before exiting
```
(on stderr; exit 141). It appears with any `| head` on `status`, so it shows up whenever someone skims `status` output.

## Comments

> *This was generated by AI during triage.*

### Triage, 2026-10-20

**Verification:** Works as designed and tested. `status --target dev | head -1` exits 141 and prints `Output closed: cleaning up before exiting` to stderr. The stream error handler treats closed output as an interruption with that notice (`src/cli/process.ts:72-82`). Exit 141 and the notice are designed (process.ts header, spec story 89) and tested (`cli-interruption.test.ts`). `--help | head -1` exits 0 only because it finishes writing before the pipe closes.

## Brief (ready-for-human)

**Category:** enhancement
**Summary:** Decide whether closed output (`| head`) should still print a notice.

**Current behavior:**
When stdout closes early, the CLI prints "Output closed: cleaning up before exiting" to stderr, cleans up and exits 141.

**Desired behavior (once decided):**
Piping to `head` exits 141 after cleaning up, as today. The notice is printed or not, as decided.

**Key interfaces:**
- The CLI's interruption handling for closed output and its notice text.
- Spec story 89.

**Acceptance criteria (once decided):**
- [ ] `status | head -1` prints only the first line (if silent), still exits 141 and still cleans up.
- [ ] The interruption test is updated to match.

**Out of scope:**
- Exit codes for signals.

**Why not delegated:** it reverses a specified, tested behaviour.
**Decision needed:**
- Keep exit 141 and cleanup, drop the notice for closed output only (recommended: other CLIs are quiet here, and the notice isn't actionable).
- Keep as is and close as wontfix.

### Decided, 2026-10-21

The maintainer chose: **drop the notice for closed output.** Exit code 141 and the cleanup stay; nothing is printed when stdout closes. Notices for signals (Ctrl+C, SIGTERM) are unchanged. Spec story 89 is updated if it names the notice.

**Acceptance criteria:** the brief's two, silent case.
