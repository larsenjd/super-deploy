# 176: In the menu, disposable preselects "yes" and doesn't show the target's current flag

**Status:** resolved
**Category:** enhancement
**Severity:** low
**Area:** disp
**Round:** 2

## What I did
`pnpm exec super-deploy` (the menu) in a terminal → `disposable` → target `prod` (not disposable, 2,000 rows).

## Expected
The question shows whether `prod` is disposable now, and preselects the change it would make (or the safe answer, "no"). Its wording is a question, not the flag's help text.

## Actual
```
◆  yes to make the target disposable, no to make it not disposable
│  ● yes
│  ○ no
```
Pressing Enter twice leads to `Mark target prod as disposable`. The YES confirmation still stands between that and the change, which is why this is low. On an already-disposable target, the preselected "yes" just ends with `Target qa is already disposable: nothing changed`.

## Notes
Every target gets the same default, production included, and the menu has no way to show which way the flag is set now (status shows "(disposable)").

### Triage, 2026-10-21

**Verification:** CONFIRMED in a pseudo-terminal. Menu → `disposable` → target `qa` asked `yes to make the target disposable, no to make it not disposable`, with `yes` selected.
- Root cause:
  - The `--set` option has no menu `question`, so the menu asks with its `--help` description (`menuQuestion`, `cli/prompts.ts:246-248`; the field was added for round 1's 38).
  - A `choice` question is a select with no initial value, so the first choice, `yes`, is preselected (`cli/prompts.ts:216-227`).
  - The menu never connects to a target before running the command, so it can't know the current flag.
- The spec says the menu's yes/no questions default to no when it matters ("commands ask yes/no (default no) when it matters"), and `yes` comes first only because of the order of `choices`.
- The YES confirmation is still required, so nothing changes without typing YES.

## Brief (ready-for-human)

**Category:** enhancement
**Summary:** The menu's `disposable` question reads as a question and doesn't steer every target, production included, toward "yes".

**Current behavior:**
Whatever the target, the menu asks with the flag's help text and preselects `yes`. On an already-disposable target the default path ends with `Target qa is already disposable: nothing changed`.

**Desired behavior (once decided):**
- The `--set` option gets a menu question, e.g. `Make target <name> disposable?` (or a static `Make the target disposable?`).
- The preselected answer is decided below.
- `--help` is unchanged.

**Key interfaces:**
- `OptionDefinition.question` for the `disposable` command's `set` option.
- The `choice` option kind: a way to say which choice is preselected, or to compute it from the project and the answers so far (the target).

**Acceptance criteria (once decided):**
- [ ] Pseudo-terminal: choosing `disposable` and a target from the menu shows the new question with the agreed preselection.
- [ ] `disposable --help` is unchanged.
- [ ] Other choice options are asked as before.

**Out of scope:**
- The YES confirmation itself.
- Rewording other options' menu questions.

**Why not delegated:** showing the current flag means the menu connects to the target before the command runs, which it doesn't do anywhere today. Preselecting a fixed answer is a smaller UX choice.
**Decision needed:**
- **(recommended)** A static question and `no` preselected, matching the spec's "default no". No connection from the menu. The current flag stays visible in `status` and in the YES confirmation (which could add `Now: disposable` / `Now: not disposable`).
- After the target is chosen, the menu reads its flag, says it in the question (`Target qa is disposable now. Make it not disposable?`) and preselects the change. This needs a connection, and a way for a choice to depend on an earlier answer.
- Keep `yes` first and add only the menu question.

### Decided, 2026-10-21

The maintainer chose: **preselect "no", and show the target's current flag.**
- After the target is chosen, the menu reads the target's current flag and shows it in the question, e.g. `Target qa is not disposable now. Make it disposable?`, with **no** preselected whatever the current value.
- If the flag can't be read (the target is unreachable), the question says so and still preselects no.
- The YES confirmation adds `Now: disposable` / `Now: not disposable`.

**Acceptance criteria:**
- [ ] Pseudo-terminal test: for a non-disposable target the menu question names the current flag and "no" is selected; same for a disposable target.
- [ ] The YES confirmation shows the current flag.
