# 112: The README calls dev "disposable", but deploy-draft and rebuild say dev is not disposable

**Status:** resolved
**Category:** bug
**Severity:** low
**Merged:** 165
**Area:** newproj
**Round:** 2

## What I did
New project, after `deploy --target dev`:
```sh
pnpm exec super-deploy deploy-draft --target dev --with-seed   # in a terminal
```

## Expected
From the README: "`dev` is local and disposable: with no command running, delete the `.super-deploy` folder ..." ("Connecting
to dev"), and "A disposable target is one you may wipe and experiment on, such as your own `dev` database". I read that
as `dev` being disposable out of the box.

## Actual
```
Error: deploy-draft only runs on disposable targets, and target dev is not disposable (flag it with disposable --target dev --set yes if it is safe to wipe): nothing changed
```
`disposable --target dev --set yes` (typing YES) fixed it, and `deploy-draft` and `rebuild` then worked well.

## Notes
The README uses "disposable" in two senses: plain English ("you can throw it away") and the flag that the guarded commands
check. Saying that `dev` starts unflagged, and that `disposable --target dev --set yes` is the first step to use
`deploy-draft` or `rebuild` on it, would clear this up.

**Verification:** CONFIRMED with the built CLI. On a fresh project with `dev` deployed and a draft, `deploy-draft --target dev` in a pty refuses: "target dev is not disposable (flag it with disposable --target dev --set yes if it is safe to wipe): nothing changed". The template README says "`dev` is local and disposable" ("Connecting to dev") and "A disposable target is one you may wipe and experiment on, such as your own `dev` database" ("Disposable targets and the guarded commands").

**By design:** `dev` starting unflagged is intended. The spec's history schema says "new targets are not disposable". Story 77 keeps the flag inside the target's database, and story 81 requires typing `YES` at a terminal to set it. So `init` (or a first deploy) flagging `dev` would bypass the YES rule; that stays out. What's wrong is the README using the word in its plain sense next to the flag.
