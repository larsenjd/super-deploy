# 08: `init` says "Next: pnpm install", but the README says to run `git init` first

**Status:** ready-for-agent
**Category:** bug
**Severity:** low
**Area:** newproj

## What I did
```sh
mkdir shop && cd shop
node /path/to/super-deploy/dist/cli.js init
```

## Expected
The printed next steps match the README: `git init`, then `pnpm install`.

## Actual
```
Initialised a super-deploy project in .
Next: pnpm install, add CREATE statements under data-model/desired-schema/, then run draft
```
The README's Getting started says to run `git init` first, because otherwise
Husky doesn't install the pre-commit hook ("If you install before `git init`,
run `pnpm install` again afterwards"). Someone who follows the CLI's hint ends
up without the hook and doesn't know it.

## Notes
Also, "Initialised a super-deploy project in ." prints "." rather than the
directory's path.

## Agent Brief

**Category:** bug
**Summary:** `init`'s printed next steps match the README (`git init` before `pnpm install`), and its first line names the directory.

**Current behavior:**
After `init`, the CLI prints "Initialised a super-deploy project in ." and "Next: pnpm install, add CREATE statements under data-model/desired-schema/, then run draft". Someone who follows it without running `git init` first ends up with no pre-commit hook and isn't told.

**Desired behavior:**
- When the directory isn't inside a git work tree, the next steps start with `git init`, then `pnpm install`, then the rest.
- When it is already inside a git work tree, `git init` is left out.
- The first line names the project directory by its absolute path (or its basename), never ".".
- `init --adopt` output is unchanged unless it prints the same lines.

**Key interfaces:**
- The `init` command's `CommandDefinition` (its result rendering) and the result type `init` returns. The API may need to report whether the project is inside a git work tree, or the CLI can check.

**Acceptance criteria:**
- [ ] At the CLI seam, `init` in a fresh temp directory with no git prints next steps that start with `git init` and then `pnpm install`.
- [ ] `init` in a directory that is already a git repository prints next steps without `git init`.
- [ ] The first line doesn't print "."; `cli-init.test.ts`'s assertion of the "." form is updated.

**Out of scope:**
- Changing what `init` writes.
- Running `git init` automatically.
