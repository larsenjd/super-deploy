# 163: rebuild's refusal for a superuser's extension suggests changing its owner, which PostgreSQL can't do

**Status:** resolved
**Category:** bug
**Severity:** low
**Area:** disp
**Round:** 2

## What I did
Disposable shared-server target `qa` (`managedSchema: "app"`, deploy role `qa2_disp_deployer`, not a superuser). As the superuser:
```sql
create extension citext schema app;
```
Then `pnpm exec super-deploy rebuild --target qa --to 2` in a terminal.

## Expected
A refusal whose remedies all work.

## Actual
```
Error: rebuild can't wipe schema app on target qa: the deploy role can't drop extension citext (owned by postgres). Drop it, change its owner to the deploy role, or ask its owner to, then run rebuild again (nothing changed)
```
PostgreSQL has no way to change an extension's owner:
```
alter extension citext owner to qa2_disp_deployer;   -- ERROR: syntax error at or near "owner"
reassign owned by postgres to qa2_disp_deployer;     -- ERROR: cannot reassign ownership of objects owned by role postgres because they are required by the database system
```

## Notes
The refusal before YES is good: the race variant (extension created while the prompt waited) rolls back cleanly too. Only the advice is wrong for extensions. Workable remedies: the superuser drops it, or, for a trusted extension like citext, the deploy role creates it itself so it owns it. The README's rebuild bullet has no advice of its own, so the message is all a user gets.

## Agent Brief

**Category:** bug
**Summary:** `rebuild`'s refusal for an extension the deploy role can't drop gives only advice that works for extensions.

**Current behavior:**
For every object it can't drop, including an extension, `CannotWipeError` says "Drop it, change its owner to the deploy role, or ask its owner to". An extension's owner can't be changed with `ALTER`.

**Desired behavior:**
- For an extension the deploy role doesn't own, the advice is to have its owner (or a superuser) drop it, e.g. `DROP EXTENSION citext CASCADE`. It doesn't suggest changing the owner.
- Objects that aren't extensions keep today's advice. Extension members in another schema keep theirs ("take it out of its extension ... or drop the extension, as its owner").
- A refusal listing both kinds gives each kind its own advice, as it already does for extension members.
- The README's `rebuild` bullet says, in a few words, what to do about such an extension.

**Key interfaces:**
- `CannotWipeError`'s message, built from `UndroppableObject[]`. Tell an extension apart from other objects (its `object` starts with `extension`, or add a field).

**Acceptance criteria:**
- [ ] A superuser-owned extension in the managed schema gives a refusal that names it and its owner, suggests dropping it as its owner, and doesn't say "change its owner".
- [ ] A superuser-owned table in a schema the deploy role doesn't own still gets the "change its owner" advice.
- [ ] A refusal with both an extension and another object gives each its own advice, in one message.

**Out of scope:**
- Letting the deploy role own extensions, or adding extensions to the desired schema (refused in V1).
- The other ownership refusals' layout (121).
