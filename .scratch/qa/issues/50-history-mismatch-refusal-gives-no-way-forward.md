## Agent Brief

**Category:** enhancement
**Summary:** Refusals for a recorded history that doesn't match the repo say what to do next.

**Current behavior:**
When a target's recorded migrations don't match the project's, `deploy` refuses and `status` lists the reason under "Deploy would refuse". Examples are a migration the repo lacks, a different name, a different content hash or chain hash, and a Recovery the repo lacks or that differs. The message states the mismatch and stops there, so the user doesn't know how to get out.

**Desired behavior:**
Each history-mismatch reason ends with a next step that fits it:
- A migration the repo lacks, or one with a different name or hash: restore the migration folder (name it) from version control. Say why: a migration a target has recorded must never change, so put new changes in a new migration.
- A Recovery mismatch gets the same advice for the Recovery's folder.
- The chain-hash case says an earlier migration changed, and names the first one that differs if it is known.
- The reason `draft` (a target holding a deployed draft) is unchanged here (issue 67 covers it).

The same wording appears in `deploy`'s pre-flight refusal, in `status`'s "Deploy would refuse" list, and in `mark`'s refusal, since they share the reasons.

**Key interfaces:**
- The pre-flight history comparison and the reason objects it returns (`reason: "not-in-repo" | "name" | "content-hash" | "chain-hash" | ...`) and their message text.
- `PreflightFailedError` (or whichever error `deploy` throws for failed pre-flight checks): unchanged code, longer message.

**Acceptance criteria:**
- [ ] API seam: deploying after changing a recorded migration's content throws a pre-flight error whose message names the migration's folder and says to restore it from version control and put the change in a new migration.
- [ ] API seam: deploying after deleting a recorded migration from the repo gives a message with the same advice.
- [ ] `status` lists the same text under "Deploy would refuse".
- [ ] The `draft` reason's message is unchanged.

**Out of scope:**
- `unfinalize` warning that a migration may be deployed (issue 10).
- `status`'s exit code when a deploy would refuse (issue 11).
- README text (issue 15).
