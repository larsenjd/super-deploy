## Agent Brief

**Category:** enhancement
**Summary:** The drift refusal points to `mark` when migrations are pending, and doesn't tell a `status` user to run `status`.

**Current behavior:**
When a target has drifted, `deploy` refuses and `status` exits 1, both with a `DriftError` whose message ends "Deployments refuse until it matches them again (status --target X lists the differences)". The message is the same whether migrations are pending or not, and whether `deploy` or `status` raised it. A common cause of drift is a hotfix applied by hand that a pending migration then catches up with, which `mark` exists for. Nothing points to `mark`.

**Desired behavior:**
- When the target has pending migrations, the drift message adds that, if the target's changes are those of the next pending migration applied by hand, `mark --target X` records it as deployed.
- When there are no pending migrations, the message doesn't mention `mark`.
- When `status` raises the error, the message doesn't tell the user to run `status`. It still says deployments refuse until the target matches its migrations again.
- `deploy`'s refusal keeps pointing to `status --target X` for the list of differences.

**Key interfaces:**
- `DriftError`: its message must know whether migrations are pending and which command raised it (e.g. extra fields on its payload or constructor). Keep its `code` unchanged.
- `driftBetween` / `status` / `deploy`: whichever builds the error passes the pending count and the caller.

**Acceptance criteria:**
- [ ] API seam: `deploy` on a drifted target with a pending migration throws a `DriftError` whose message mentions `mark --target <name>`.
- [ ] API seam: `deploy` on a drifted target with no pending migrations throws a `DriftError` whose message doesn't mention `mark`.
- [ ] CLI seam: `status --target X` on a drifted target exits 1, and stderr doesn't contain "status --target X lists the differences".
- [ ] `deploy`'s message still names `status --target X` for the differences.

**Out of scope:**
- Detecting that the drift is exactly the next pending migration (that needs a second replica per run).
- Changing how drift is detected or listed.
- README text for `mark` (issue 15).
