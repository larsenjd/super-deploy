# 05: The template's own `dev` target prints a superuser warning on every command

**Status:** resolved
**Category:** enhancement
**Severity:** low
**Area:** newproj

## What I did
```sh
node .../dist/cli.js init && git init && pnpm install
pnpm exec super-deploy status --target dev
pnpm exec super-deploy deploy --target dev
```

## Expected
The out-of-the-box configuration produces no warnings, or the warning tells me
how to fix it for the embedded server.

## Actual
Every command that touches `dev` prints:
```
warning: The deploy role "super_deploy" on target dev is a superuser: deploy with a role that isn't, so deploy-time SQL can't reach beyond the database
```
The role and the server are created by the template's `embeddedPostgres(...)`,
and nothing in the README, the config or the warning says how to use a
non-superuser there. A new user's first deploy warns them about something they
didn't set up and can't change, which teaches them to ignore warnings.

## Notes
Either the embedded dev target should deploy as a non-superuser itself, or
this warning should be suppressed or reworded for it.

### Triage, 2026-10-20

**Verification:** CONFIRMED, and intended by the test docs. Every `status` and `deploy --target dev` in a fresh project prints the superuser warning. `docs/agents/testing.md` says embedded targets log in as the superuser `super_deploy`, so `deploy` and `status` always carry the warning. Neither the spec nor REFINEMENTS discusses exempting embedded targets, and the README never mentions it. The warning comes from `deployRoleWarnings` (`src/deploy/preflight.ts:262-292`). The embedded adapter hard-codes user and password `super_deploy` and uses it as the initdb superuser (`src/adapters/embedded-postgres.ts:50-51`, `:134`).

## Brief (ready-for-human)

**Category:** enhancement
**Summary:** The template's own `dev` target shouldn't warn on every command about a role the user didn't choose.

**Current behavior:**
The embedded adapter's `target()` connects as the cluster superuser `super_deploy`. The deploy pre-flight checks warn that the deploy role is a superuser on every `status` and `deploy` against `dev`. The warning tells the user to "deploy with a role that isn't", which they can't do for the embedded server.

**Desired behavior (once decided):**
A fresh project's `status --target dev` and `deploy --target dev` print no warning the user can't act on. Real targets that connect as a superuser still get the warning.

**Key interfaces:**
- The embedded adapter's `target(database)`: which role it connects as.
- The pre-flight deploy-role warnings: whether they know the target is embedded.
- The template README, if the outcome is documentation.

**Acceptance criteria (once decided):**
- [ ] In a fresh `init` project, `status --target dev` and `deploy --target dev` produce no superuser warning (or the README explains it, if that option is chosen).
- [ ] A `postgresTarget` connecting as a superuser still gets the warning.
- [ ] The testing doc's note about embedded targets always carrying the warning is updated to match.

**Out of scope:**
- Rehearsal roles and the rehearsal cluster (see 06).
- Other pre-flight warnings.

**Why not delegated:** it's a product choice about what the embedded server is for.
**Decision needed:**
- Have the embedded `target()` create and connect as a non-superuser deploy role that owns the database, so `dev` behaves like a real target (recommended).
- Suppress the superuser warning for embedded targets.
- Keep it and document in the README that `dev` warns by design.

### Decided, 2026-10-21

The maintainer chose: **the embedded target connects as a non-superuser deploy role that owns the database**, so `dev` behaves like a real target. This completes the brief above.

- `embeddedPostgres(...).target(database)` creates, on first connect, a `LOGIN` role that is not a superuser and has no predefined roles (name and password fixed and local-only, like today's `super_deploy` credentials), makes it the owner of the target database, and connects as it. Server setup that needs the superuser (creating the database and the role) keeps using `super_deploy`.
- The deploy role owns the database, so it owns `public` through `pg_database_owner` and passes the ownership pre-flight; it has `CREATE` on the database for the history schema.
- Rehearsals are unaffected (06 moves them to their own server).
- README: the `dev` section names the role `dev` deploys as.

**Blocked by:** None (can start immediately). 06 and 14 build on this ticket's changes to `adapters/embedded-postgres.ts`.

**Acceptance criteria** (replacing the "once decided" ones):
- [ ] In a fresh `init` project, `status --target dev` and `deploy --target dev` print no superuser warning (API and CLI seams).
- [ ] `dev`'s deploy role is not a superuser, owns the `dev` database, and deploys a migration with a table, view and function (API seam).
- [ ] A `postgresTarget` connecting as a superuser still gets the warning.
- [ ] `docs/agents/testing.md`'s note that embedded targets always carry the superuser warning is updated.
