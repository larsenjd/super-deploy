## Agent Brief

**Category:** enhancement
**Summary:** A syntax error in `super-deploy.config.ts` is reported with its line and the source line.

**Current behavior:**
When the config file has a TypeScript syntax error, loading the project fails with "Failed to load super-deploy.config.ts: <message>". Node's error does know the location, in the first line of its stack (`<file URL>:<line>`), followed by the source line and a caret. The message drops it, and the location only appears with `--debug`.

**Desired behavior:**
For a syntax error while loading the config, the message reads `super-deploy.config.ts:<line>: <message>` (project-relative path), followed by the offending source line. If the location can't be found, the message stays as it is today. Other config errors (validation, missing default export, runtime throws) are unchanged.

**Key interfaces:**
- `loadProject` and the error it throws when the config fails to load (keep its error class and `code`).
- Node's `SyntaxError` for type stripping: `code === "ERR_INVALID_TYPESCRIPT_SYNTAX"`, with the location in the first stack line. Plain JS `SyntaxError`s from the config's imports may use the same shape.

**Acceptance criteria:**
- [ ] API seam: a config with a syntax error on line N makes `loadProject` throw an error whose message starts with `super-deploy.config.ts:N:` and contains the source line.
- [ ] CLI seam: the same project gives that message on stderr without `--debug`, exit 1.
- [ ] A config that throws at run time, or fails validation, gives exactly the message it gives today.

**Out of scope:**
- Column numbers if Node doesn't provide them reliably.
- Locations for errors inside modules the config imports.
