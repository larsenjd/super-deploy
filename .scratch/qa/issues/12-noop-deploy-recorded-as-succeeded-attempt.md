**Status:** resolved
**Category:** enhancement
**Severity:** low
**Area:** newproj

## What I did
With `qa` up to date:
```sh
pnpm exec super-deploy deploy --target qa
pnpm exec super-deploy status --target qa
```

## Expected
Either no attempt is recorded (nothing happened), or it shows up as a no-op.

## Actual
```
Target qa is up to date: nothing to deploy
```
```
Recent attempts:
  #7 deploy succeeded migration 5 by jonathanl at 2026-10-20T19:45:30.296Z
  #6 deploy succeeded by jonathanl at 2026-10-20T19:45:21.789Z
  #5 deploy succeeded migration 4 by jonathanl at 2026-10-20T19:44:44.294Z
```
Attempt #6 reads like a successful deploy with the migration missing. With CI
retrying deploys, "Recent attempts" will fill up with these and push the
useful entries out.

### Triage, 2026-10-20

**Verification:** CONFIRMED, but recording the attempt is BY-DESIGN. A second `deploy` with nothing pending returned `deployed: []`, and `status` lists it as "#2 deploy succeeded by ..." with no migration range.

A no-op deploy still runs the pre-flight checks and the drift check, and spec story 63 wants every attempt recorded. A no-op deploy that fails on drift must still appear, so the reporter's alternative, recording nothing, is out. The fix is display only: the attempt line rendered by `describeAttempt` in the CLI.

## Agent Brief

**Category:** enhancement
**Summary:** Show a deploy attempt that deployed nothing as "nothing to deploy" in `status`'s attempt list.

**Current behavior:**
A deploy with nothing pending is recorded as an attempt, which is correct (every attempt is recorded). `status` then shows it as "#6 deploy succeeded by <user> at <time>". That reads like a successful deploy whose migration is missing.

**Desired behavior:**
In `status`'s "Recent attempts", a deploy attempt with no migration range and outcome succeeded reads "#6 deploy succeeded, nothing to deploy, by <user> at <time>" (exact wording is the implementer's call). A failed no-op deploy, such as one refused on drift, keeps its failure wording. Attempts with a range are unchanged.

**Key interfaces:**
- `AttemptRecord` (no change expected) and the CLI's rendering of an attempt for `status`.

**Acceptance criteria:**
- [ ] After a second `deploy` with nothing pending, `status` shows that attempt as nothing-to-deploy (CLI seam).
- [ ] An attempt that deployed migrations is rendered as before.
- [ ] Every deploy attempt is still recorded in the history schema.

**Out of scope:**
- Not recording no-op attempts.
- Filtering or paging the attempt list.
