# 07: The pre-commit hook refuses any commit while a draft exists, which the README doesn't say

**Status:** ready-for-human
**Category:** enhancement
**Severity:** low
**Area:** newproj

## What I did
```sh
# edit the desired schema
pnpm exec super-deploy draft --name "rename display name"
# write data-model/draft/pre-migration.sql and seed-data.sql
git add -A && git commit -m "wip draft"
```

## Expected
Either I can commit (and push for review) a draft in progress, or the README
says that the hook blocks it and what the intended workflow is (finalize
before committing? `--no-verify`?).

## Actual
```
warning: Draft rename-display-name is not finalized yet
Error: Validation failed with 1 warning (--strict): Draft rename-display-name is not finalized yet
husky - pre-commit script failed (code 1)
```
The same happens for a desired-schema edit with no draft yet ("The desired
schema differs from migration 00003-drop-notes's snapshot and no draft covers
it; run draft").

## Notes
The README's Files section only says `pnpm precommit` runs `super-deploy
validate --strict`. So you can't commit WIP or share a draft (with its
hand-written pre-migration script and seed data) on a branch for review
before finalizing, unless you use `--no-verify`. If that's intended, it
should be documented.

## Brief (ready-for-human)

**Category:** enhancement
**Summary:** Decide whether the template's pre-commit hook may block committing a draft in progress, and document the answer.

**Current behavior:**
Any commit made while a draft exists, or while the desired schema has undrafted changes, fails the pre-commit hook. A draft can't be shared on a branch for review before it's finalized unless you use `git commit --no-verify`. The README doesn't say so.

**Desired behavior (once decided):**
Either a draft can be committed and pushed for review, while other `validate` problems still block the commit. Or the README states that the hook blocks work-in-progress commits and gives the intended workflow.

**Key interfaces:**
- `validate`'s warnings and the `--strict` flag (what counts as fatal).
- The template's `precommit` script and Husky hook.
- The template README's Files and Getting started sections.

**Acceptance criteria (once decided):**
- [ ] The behaviour of committing with a draft present is as decided and covered by a CLI test of `validate`.
- [ ] The README says what the hook blocks and what to do with work in progress.
- [ ] CI usage of `validate --strict` still fails on an unfinalized draft, if that's still wanted there.

**Out of scope:**
- Other `validate` checks.
- The example project's hook, unless the template's changes.

**Why not delegated:** it's a workflow decision (does `main` ever hold a draft?).
**Decision needed:**
- Let the hook pass "draft not finalized" and "no draft covers it" (for example a `--strict` mode that skips work-in-progress warnings, used only by the hook), and keep CI strict (recommended).
- Keep blocking and document "finalize before committing, or `--no-verify`".
