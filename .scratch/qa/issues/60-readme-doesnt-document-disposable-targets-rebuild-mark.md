## Expected
A section explaining:
- what a disposable target is, that the flag lives in the target's own
  `deployment_history` schema (not in `super-deploy.config.ts`), and how to set
  and clear it (`disposable --target X --set yes|no`);
- `deploy-draft` (and that the target then refuses `deploy` and `mark` until
  `rebuild` resets it), `--with-seed`;
- `rebuild --to N`: what it drops (only the managed schema? dependent objects
  elsewhere? extensions?), what it keeps (database privileges, other schemas,
  default privileges), and that it never loads seed data;
- `mark`: when to use it, what "matches a replica exactly" means, and the fact
  that it ignores column order and ownership;
- that all four need a terminal and refuse in CI (`CI=true`).

## Actual
Only one hit: the Permissions section says "`rebuild` leaves the managed
schema's grants exactly as the migrations declare" and that `rebuild` fails on
grants an administrator made, without ever saying what `rebuild` is. The words
"disposable", "deploy-draft" and "mark" don't appear. The Seed data section
says rehearsals load seed data and it "is never loaded once the migration is
finalized", but not that `deploy-draft --with-seed` loads it on a real target.

Everything I learned about these commands came from `--help`, the confirmation
boxes and error messages, e.g. that `deploy-draft` leaves the target in a state
where `deploy` refuses:

```
The target then holds the draft, not a migration: deploy refuses it until rebuild resets it
```

and that `mark` compares "column order and ownership aside" (only visible in
the confirmation box after a successful comparison).
