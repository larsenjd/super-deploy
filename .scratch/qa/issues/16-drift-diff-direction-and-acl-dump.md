# 16: Drift output: the -/+ lines are unlabelled and the reverse of the usual direction, and an ACL change prints the whole ACL

**Status:** resolved
**Category:** enhancement
**Severity:** low
**Merged:** 32
**Area:** newproj

## What I did
On the deployed `qa` target, as superuser:
```sql
grant delete on orders to newproj_app_writer;
create index orders_hand_idx on orders (status);
```
```sh
pnpm exec super-deploy status --target qa
```

## Expected
A diff that says which side is which (expected by migrations vs. found on
target), in the usual direction (`-` expected, `+` found), and for grants
just the grant that differs, e.g. `+ grant DELETE on orders to newproj_app_writer`.

## Actual
```
Drift (the target differs from its recorded migrations):
  extra: index orders_hand_idx
    - index: CREATE INDEX orders_hand_idx ON public.orders USING btree (status) valid=true clustered=false replident=false
  changed: table orders
    - acl: orders {<owner>:DELETE/<owner>,<owner>:INSERT/<owner>,<owner>:MAINTAIN/<owner>,<owner>:REFERENCES/<owner>,<owner>:SELECT/<owner>,<owner>:TRIGGER/<owner>,<owner>:TRUNCATE/<owner>,<owner>:UPDATE/<owner>,newproj_app_reader:SELECT/<owner>,newproj_app_writer:DELETE/<owner>,newproj_app_writer:INSERT/<owner>,newproj_app_writer:SELECT/<owner>,newproj_app_writer:UPDATE/<owner>}
    + acl: orders {<owner>:DELETE/<owner>,...,newproj_app_writer:INSERT/<owner>,newproj_app_writer:SELECT/<owner>,newproj_app_writer:UPDATE/<owner>}
```
- The *extra* index is shown with `-`, and the `-` ACL is the one with the
  hand-made `DELETE`. So `-` means "on the target", the opposite of `diff`/git
  convention where `-` is the baseline. I first read it backwards.
- To find the one grant that changed, you have to compare two 13-entry ACL
  strings by eye.
- The schema-level case is the same (`changed: schema app`, full ACL on both
  lines).

### Triage, 2026-10-20

**Verification:** CONFIRMED.
- *Direction:* `factDifferences` (`src/verification/catalog.ts:302-318`) makes `-` the facts only on the target (actual) and `+` the facts only expected by the migrations (the replica). The CLI prints them unlabelled (`src/cli/definitions.ts:711-720`, `:819-830`); the only explanation is a code comment. That's the reverse of the git convention.
- *ACL dump:* the acl fact is one sorted array per object (`catalog.ts:36-40`, `:183-205`), so one changed grant prints the whole ACL twice. Reproduced.
- *From 32:* quoted role names are double-escaped (`{"\"Rep_f00c\":USAGE/<owner>",...}`), from `quote_ident` inside `array(...)::text`. Tables print without their schema, because the catalog read pins `search_path` to the managed schema. The grantor is always written `<owner>`, so an admin-made grant (see 27) looks like the owner's.
- The side note about "Drift: not checked" on a deployed draft is 67.

## Brief (ready-for-human)

**Category:** enhancement
**Summary:** Make drift output say which side is which and show only the grant that differs.

**Current behavior:**
Drift lines are an unlabelled `-`/`+` pair, where `-` is what the target has and `+` is what the migrations expect. A grant change prints the object's whole ACL on both lines. Quoted role names are double-escaped, and objects in the managed schema print without their schema.

**Desired behavior (once decided):**
- Each difference says which side it's on, in words or in the agreed direction.
- A grant difference names only the grantee and privilege that differ.
- Names are schema-qualified and quoted once.

**Key interfaces:**
- The catalog comparison's facts (`catalogFacts`, `catalogDifferences`): one fact per ACL item instead of one per object.
- The drift difference type used by `status`, the deploy refusal, rehearsal mismatches and `mark`.
- The CLI's drift rendering.

**Acceptance criteria (once decided):**
- [ ] An extra hand-made grant shows as one line naming the grantee and privilege, on the target's side.
- [ ] A revoked declared grant shows as one line on the migrations' side.
- [ ] A role needing quotes appears quoted once.
- [ ] Objects in the managed schema are schema-qualified.
- [ ] Rehearsal mismatches and `mark` comparisons still detect the same differences (existing drift and rehearsal tests pass, updated for the new format).

**Out of scope:**
- Detecting grants the deploy role can't revoke (27).
- Ownership (28).

**Why not delegated:** the output format and direction are user-facing choices. Splitting the ACL fact per item is mechanical once they're made.
**Decision needed:**
- Label the sides in words ("on the target:" / "expected by migrations:") and drop bare `-`/`+` (recommended).
- Keep `-`/`+` but flip to the git convention (`-` expected, `+` found), with a legend line.
- Whether to show the grantor when it isn't the owner (recommended yes, given 27).

### Narrowed, 2026-10-20

ADR-0006 puts privileges, ownership and row-level security outside the system in V1 (`.scratch/super-deploy/issues/28-privileges-out-of-scope.md`). The catalog comparison stops reading ACLs, so the ACL dump, double-escaped role names and the grantor question go away. What remains: label the sides of a difference, or flip them to the git convention, and schema-qualify names. Ignore the grant-specific acceptance criteria.

### Decided, 2026-10-21

The maintainer chose: **label the two sides in words**, dropping bare `-`/`+`. ADR-0006 already removed the grant and ACL parts (see "Narrowed").

- Each difference reads e.g. `table customers: on the target: <line>` / `expected by migrations: <line>`, or for one-sided differences `only on the target:` / `missing from the target:`. The same words are used by `status`, the deploy drift refusal and `mark`.
- Rehearsal mismatches, which compare a replay with the desired schema, use their own pair of labels: `from the migrations:` / `from the desired schema:`.
- Object names are schema-qualified and quoted once.

**Acceptance criteria** (replacing the brief's, whose grant criteria are void):
- [ ] An extra hand-made column shows under `only on the target`, a dropped index under `missing from the target`, a changed column type with both labelled sides (API and CLI seams).
- [ ] A rehearsal mismatch uses its own labels.
- [ ] Objects are schema-qualified; a name needing quotes is quoted once.
- [ ] Existing drift, mark and rehearsal tests pass, updated for the new format.
