**Verification:** CONFIRMED. Reproduced: `draft` refuses `execute 'select 1'` with `... [plpgsql-dynamic-sql]` and no override hint. A `pg_notify` call (`denylisted-call`) is the same. ## Agent Brief

**Category:** enhancement
**Summary:** Overridable refusals say how to override them, and the README documents the override marker for hand-written SQL.

**Current behavior:**
Rule violations in the `risk` category can be overridden with the marker comment `-- OVERRIDE SUPER-DEPLOY REFUSAL: <reason>` on the line before the statement. Examples are dynamic SQL in PL/pgSQL and denylisted function calls. The refusal message doesn't say so. The README mentions the marker only in the adoption section, so someone writing a desired schema or script by hand can't find it.

**Desired behavior:**
- A violation of an overridable rule with no marker before it ends with a short hint: if the statement is safe, put `-- OVERRIDE SUPER-DEPLOY REFUSAL: <reason>` on the line before it. Take the marker text from the same source the parser uses.
- Violations of rules that can't be overridden carry no hint.
- The existing hint for an old marker form is unchanged.
- The template README gets a short section on the override marker. It covers where it goes, that it needs a reason, which refusals it applies to (risk rules), and that the reason is recorded. The adoption section links to it.

**Key interfaces:**
- The rule catalogue's categories (`risk` is the overridable one) and `isOverridable`.
- The override marker prefix (`markerPrefix`) and `applyMarker`, which already decides marker handling per violation.

**Acceptance criteria:**
- [ ] SQL-analysis unit test: a `plpgsql-dynamic-sql` violation without a marker has the override hint in its message.
- [ ] SQL-analysis unit test: a violation of a non-overridable rule (e.g. `unsupported-object`) has no override hint.
- [ ] A statement with a valid marker still passes, and the old-marker hint is unchanged.
- [ ] The template README documents the marker outside the adoption section.

**Out of scope:**
- Making more rules overridable.
- Adoption's interactive override reasons.
