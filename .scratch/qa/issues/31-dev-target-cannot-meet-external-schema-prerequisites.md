# 31: With `externalSchemas` configured, the default `dev` target can't be deployed, and the docs don't say how to prepare it

**Status:** wontfix
**Category:** enhancement
**Severity:** medium
**Duplicate of:** 06
**Area:** adopt

## What I did
Adopted `qa_adopt_shop`, whose trigger function reads `auth.users` (the README's `set_author_name` example), with:

```ts
managedSchema: "app",
externalSchemas: ["auth"],
targets: { dev: { adapter: postgres.target("dev") }, shop: { ... } },
```

Then deployed the project to the local `dev` target that `init` sets up:

```sh
pnpm exec super-deploy deploy --target dev
pnpm exec super-deploy status --target dev
```

## Expected
The README explains how to give the local `dev` target what "each target needs set up outside super-deploy" (the external schema, the deploy role's grants on it, the app roles), or how to connect to the embedded server to do it.

## Actual
```
warning: The deploy role "super_deploy" on target dev is a superuser: deploy with a role that isn't, so deploy-time SQL can't reach beyond the database
Error: Target dev failed the deploy pre-flight checks: external schema "auth" does not exist (it is declared in externalSchemas)
```

The embedded server starts on a random port only while a command runs. Its `pg_hba.conf` requires a password, and neither the README nor `--help` says how to connect to it. So I found no supported way to create `auth` on `dev`, and `dev` stays undeployable for any project that uses `externalSchemas`.

## Notes
- Related rough edge: the template's own `dev` target prints the superuser warning above on every `status`/`deploy` against it. The user didn't choose that role, and the warning tells them to "deploy with a role that isn't".
- Rehearsals create placeholder roles on the same embedded server, so `dev` happened to have the app roles. External schemas get no such help.
