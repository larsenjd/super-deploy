# 04: An unset or empty connection string gives "Cannot read properties of undefined (reading 'charAt')" / "ENOTFOUND base"

**Status:** ready-for-agent
**Category:** bug
**Severity:** medium
**Merged:** 30, 53 (validation parts)
**Area:** newproj

## What I did
`super-deploy.config.ts`, following the README's advice to read the
connection string from an environment variable:
```ts
qa: { adapter: postgresTarget({ connectionString: process.env.QA_DATABASE_URL as string }) },
```
Then, in a shell where `QA_DATABASE_URL` isn't exported (easy to do: a new
terminal tab):
```sh
pnpm exec super-deploy status --target qa
```
And with `connectionString: process.env.QA_DATABASE_URL ?? ""`:
```sh
pnpm exec super-deploy status --target qa
```

## Expected
Something like: `Target qa has no connection string (connectionString is
undefined/empty): set it in super-deploy.config.ts, e.g. from an environment
variable`.

## Actual
```
Error: The deployment adapter of target qa failed to connect: Cannot read properties of undefined (reading 'charAt')
```
```
Error: The deployment adapter of target qa failed to connect: getaddrinfo ENOTFOUND base
```
Neither says the connection string is missing; the second suggests a DNS
problem with a host called "base".

## Notes
I hit this for real mid-session after opening a new shell. Guess: the
connection string is passed to `pg` without validation, which falls back to
odd defaults.

### Triage, 2026-10-20

**Verification:** CONFIRMED. `env -u QA_URL CI=1 node dist/cli.js status --target X` gave:
- `connectionString: process.env.QA_URL as string`: "failed to connect: Cannot read properties of undefined (reading 'charAt')".
- `?? ""`: "failed to connect: getaddrinfo ENOTFOUND base".
- `{ env: "QA_URL" }`: "Environment variable QA_URL is not set".

Cause: `resolveConnectionString` in `adapters/node-postgres.ts` passes `connectionString` through unchecked to `parseIntoClientConfig`. pg-connection-string calls `str.charAt(0)`, and falls back to `new URL(str, 'postgres://base')`, which is where the host `base` comes from.

## Agent Brief

**Category:** bug
**Summary:** Validate a target's connection string before connecting, with errors that name the target and say what is wrong.

**Current behavior:**
`postgresTarget({ connectionString })` hands whatever it is given to node-postgres's parser:
- `undefined` gives "Cannot read properties of undefined (reading 'charAt')".
- An empty or non-URL string gives "getaddrinfo ENOTFOUND base".
- A `mysql://` URL is accepted.

`postgresTarget({ env })` reports "Environment variable X is not set" both for an unset variable and for an empty one, and doesn't say which target needed it.

**Desired behavior:**
When a command first uses a target, its connection string is checked before any connection is attempted. Other targets keep working, so validation stays lazy and per target. Each problem gets its own `AdapterError` message naming the target:
- `connectionString` is undefined, not a string, or empty: "Target qa has no connection string (connectionString is empty)". Mention `postgresTarget({ env: ... })` as the usual way to supply it.
- `env` variable unset: "Target qa: environment variable QA_DATABASE_URL is not set".
- `env` variable set but empty: "... is empty".
- A string that isn't a `postgres://` or `postgresql://` URL, or that fails to parse: "Target qa's connection string is not a PostgreSQL URL (postgres://user:password@host:port/database)". Never echo the password.

These errors surface the same way from `status`, `deploy`, `init --adopt` and the guarded commands.

**Key interfaces:**
- `postgresTarget(source: ConnectionSource)` and the function that turns a `ConnectionSource` into a connection string.
- `AdapterError`: the message must include the target name. Either pass the target name into the check, or have the caller that wraps adapter calls add it for these errors.

**Acceptance criteria:**
- [ ] At the CLI or API seam, each of these produces its own message naming the target, exits 1, and attempts no network connection: `connectionString` undefined, `connectionString` `""`, `env` unset, `env` empty, `"not a url"`, and `mysql://u:p@localhost/db`.
- [ ] A target whose variable is unset doesn't stop commands on other targets (for example `status --target dev`) from working.
- [ ] No error message contains the password from the connection string.
- [ ] Valid `postgres://` and `postgresql://` strings, including ones with query parameters, still connect as before.

**Out of scope:**
- sslmode/TLS behaviour and pg's "SECURITY WARNING" text (issue 53).
- Connect timeouts (issue 43) and empty "connection refused" reasons (issue 42).
- README changes (issue 03).
