# 03: README says to add real targets to the config but never shows how (`postgresTarget` is undocumented)

**Status:** ready-for-agent
**Category:** enhancement
**Severity:** medium
**Merged:** 29, 13
**Area:** newproj

## What I did
After `init`, I wanted to add a `qa` target on an existing PostgreSQL server.
The README's only guidance is:

> Add real targets (QA, production) to `super-deploy.config.ts`; keep
> credentials out of it, for example by reading a connection string from an
> environment variable.

The generated `super-deploy.config.ts` only shows the embedded adapter
(`postgres.target("dev")`). Neither the README, the config's comments nor
`--help` names the adapter for a real server or its options.

## Expected
A snippet in the README (or a commented-out example in the generated
`super-deploy.config.ts`), e.g.:
```ts
import { defineConfig, postgresTarget } from "super-deploy";
...
qa: { adapter: postgresTarget({ connectionString: process.env.QA_DATABASE_URL }) },
```
with what happens when the variable is unset.

## Actual
I had to find the export by provoking TypeScript errors in a probe file
(`const a: "x" = "" as keyof typeof import("super-deploy")`), which listed
`postgresTarget`, and then its parameter type (`{ connectionString: string }`).
This works:
```ts
qa: {
  adapter: postgresTarget({
    connectionString: process.env.QA_DATABASE_URL as string,
  }),
},
```
But with `exactOptionalPropertyTypes`/`strict` in the template's tsconfig,
`process.env.X` (type `string | undefined`) doesn't type-check, so users
will reach for `as string` or `?? ""`. Both give confusing errors when the
variable is unset (see issue 04).

## Notes
- The README's Permissions section refers to "the deploy role" throughout but
  never says the deploy role is simply the user in the connection string.
- `ConnectionSource` suggests other ways to connect exist; they aren't documented
  either.

Correction: `postgresTarget({ env: "QA_DATABASE_URL" })` already exists (`ConnectionSource = { connectionString } | { env }`). ## Agent Brief

**Category:** enhancement
**Summary:** Document the configuration in the template README, with a real-target example using `postgresTarget({ env })`.

**Current behavior:**
The template README tells users to add real targets, but never shows how. It never names `postgresTarget` or its `ConnectionSource` forms, and never explains any `SuperDeployConfig` option other than those in the generated config. Users find `managedSchema`, `historySchema`, `externalSchemas`, `directory`, `lockTimeout` and `statementTimeout` only through TypeScript errors. The generated `super-deploy.config.ts` shows only the embedded `dev` target.

**Desired behavior:**
- The template README has a "Configuration" section listing every `SuperDeployConfig` option and every `TargetConfig` option, each with its meaning and default. The content comes from the JSDoc on those types:
  - `managedSchema`, default `public`
  - `historySchema`, default `deployment_history`
  - `externalSchemas`, default none
  - `directory`, default `data-model`
  - per target, `lockTimeout`, default `"5s"`, and `statementTimeout`, default none, with the accepted duration forms
- The section shows a real target added with `postgresTarget({ env: "QA_DATABASE_URL" })`. It explains that the variable is read only when that target is used, and what happens when it is unset. It mentions the `{ connectionString }` form too.
- It says the deploy role is the user in the connection string, so that the Permissions section's "deploy role" has a referent.
- The README's existing mentions of "the managed schema" and `externalSchemas` link to or agree with this section.
- The template's generated `super-deploy.config.ts` includes a commented-out real target using `postgresTarget({ env: ... })` and the import it needs. The template must still pass its `tsc` and `validate --strict`.

**Key interfaces:**
- `SuperDeployConfig`, `TargetConfig` and `Duration`: the JSDoc is the source of truth. Keep the README consistent with it.
- `postgresTarget(source: ConnectionSource)` with `{ env: string } | { connectionString: string }`.
- The template project that `init` copies: its README and `super-deploy.config.ts`.

**Acceptance criteria:**
- [ ] The template README names every `SuperDeployConfig` and `TargetConfig` key with its default, and each default matches the code.
- [ ] The README shows a `postgresTarget({ env: ... })` target and says when the variable is read.
- [ ] The README says the deploy role is the connection string's user.
- [ ] The generated `super-deploy.config.ts` contains a commented real-target example, and the template's precommit (Biome, `tsc`, `validate --strict`) still passes.
- [ ] The `init` tests still pass, updated if they assert the config's exact content.

**Out of scope:**
- Validating connection strings (issue 04) and TLS/sslmode (issue 53).
