# 130: Adoption's "Left N grants and M policies" says nothing about row-level security or default privileges it left

**Status:** ready-for-agent
**Category:** enhancement
**Severity:** low
**Area:** adopt
**Round:** 2

## What I did
```sql
-- database qa2_adopt_edge, schema core, as the deploy role
alter table core.items enable row level security;          -- no policy on it
alter table core.parts enable row level security;
alter table core.parts force row level security;
alter default privileges in schema core grant select on tables to qa2_adopt_app_reader;
grant usage on schema core to qa2_adopt_app_reader;
grant select (id, qty) on core.items to qa2_adopt_app_reader;
```
```sh
pnpm exec super-deploy init --adopt qa     # in a terminal (one override reason asked)
```
Also on `qa2_adopt_shop`: 7 grants, 1 policy, RLS enabled on `orders`.

## Expected
The summary mentions everything adoption deliberately left on the target: grants, policies, tables with row-level security enabled/forced, and default privileges, so the user knows what to recreate on `dev`/other targets by hand.

## Actual
```
Left 3 grants and 0 policies on target qa as they are: privileges and row-level security are set up outside super-deploy
```
and on `shop`: `Left 7 grants and 1 policy ...`. Two tables with RLS on (one forced, with no policy: nobody but the owner can read it) and a default-privilege rule aren't counted or named. "0 policies" next to "row-level security" could make a reader think there is none.

## Notes
The README says "adoption says how many grants and policies it left", which matches; the gap is that RLS and default privileges are the things most likely to surprise someone later (e.g. a new `dev` where every table is readable, or the app can't read a table on prod).

### Triage, 2026-10-21

**Verification:** CONFIRMED.
- `qa2t_adopt_edge` had RLS enabled on `core.items`, enabled and forced on `core.parts`, no policies, a default privilege of the deploy role in `core`, and three grants. Adoption said only `Left 3 grants and 0 policies on target qa as they are`.
- On `qa2t_adopt_shop`, with RLS on two tables (one forced), one policy and a deploy-role default privilege, it said `Left 2 grants and 1 policy`.

**Cause:** `countLeftOnTarget` (`commands/adopt.ts`) counts only ACL grants and `pg_policy` rows; `LeftOnTarget` has only `grants` and `policies`. This matches the spec (Q51, "one line saying how many grants and policies were left") and the README, so it is a gap, not a bug. ADR-0006 keeps RLS flags and default privileges on the target unmanaged, and those are exactly what a new `dev` won't have.

## Agent Brief

**Category:** enhancement
**Summary:** Adoption's summary also counts the tables with row-level security on (and forced) and the deploy role's default privileges that it left on the target.

**Current behavior:**
`Left N grants and M policies on target X as they are: privileges and row-level security are set up outside super-deploy`. Tables with row-level security enabled or forced, and default-privilege rules, aren't counted, so "0 policies" can read as "no row-level security".

**Desired behavior:**
- `LeftOnTarget` also has the number of managed-schema tables with row-level security enabled, how many of them have it forced, and the number of `pg_default_acl` entries of the deploy role in the managed schema or global (namespace 0).
- The CLI line includes them when non-zero, e.g. `Left 3 grants, 0 policies, row-level security on 2 tables (forced on 1) and 1 default privilege rule on target qa as they are: ...`.
- With none of these, the line reads as today.
- The README's "adoption says how many grants and policies it left" and the spec's Q51 sentence mention the new counts.

**Key interfaces:**
- `LeftOnTarget` (exported, in `AdoptResult`) and `countLeftOnTarget`.
- The CLI's adoption success output.

**Acceptance criteria:**
- [ ] API seam: adopting a target with RLS enabled on two tables (one forced), no policies and one default privilege for the deploy role in the managed schema returns those counts in `leftOnTarget`.
- [ ] Default privileges of other roles aren't counted.
- [ ] A target with none of them gives zeros, and the CLI line is unchanged from today's.
- [ ] README and spec updated.

**Out of scope:**
- Managing or reproducing any of these (ADR-0006).
- Dependents in other schemas (131).
