### Triage, 2026-10-21

**Verification:** CONFIRMED. `sslrootcert=/nonexistent.pem` with `verify-full`, `sslrootcert=/tmp` (a directory) with `verify-ca`, and `/nonexistent.pem` with `sslmode=disable` all gave `Target qa's connection string is not a PostgreSQL URL (…)`. `--debug` has no `Caused by:`.

**Root cause:** `urlProblem` in the node-postgres adapter checks a string by parsing it into node-postgres's client config, and maps any exception to `not-postgres-url`, dropping it. pg-connection-string reads `sslrootcert`, `sslcert` and `sslkey` with `readFileSync` while parsing, before looking at `sslmode`, so an unreadable file throws ENOENT or EISDIR there. That is also why `sslmode=disable` fails: libpq doesn't read the file when it doesn't use TLS.

## Agent Brief

**Category:** bug
**Summary:** A connection string whose `sslrootcert`, `sslcert` or `sslkey` file can't be read gets an error naming the parameter, the path and the reason.

**Current behavior:**
A missing, unreadable or directory `sslrootcert` (or `sslcert`/`sslkey`) makes every command that uses the target fail with `Target qa's connection string is not a PostgreSQL URL (postgres://user:password@host:port/database)`, the underlying error is lost even with `--debug`, and it fails even with `sslmode=disable`.

**Desired behavior:**
- The error names the target, the parameter, the path as given and as resolved, and the reason, e.g. `Target qa: sslrootcert file missing-ca.pem (/home/me/app/missing-ca.pem) can't be read: no such file or directory. A relative path is read from the directory the command runs in.` The underlying error is its cause, shown by `--debug`.
- It is still checked before any connection is attempted, and never echoes the password.
- With `sslmode=disable`, the file parameters are ignored, as libpq does, and the command connects.
- A string that really isn't a PostgreSQL URL keeps today's message.
- The same applies to `postgresRehearsal`'s connection string.

**Key interfaces:**
- `ConnectionStringProblem` and `ConnectionStringError`: a new problem kind for an unreadable file parameter.
- The check that runs before connecting (`urlProblem` and the client-config builder).

**Acceptance criteria:**
- [ ] API or CLI seam: `sslmode=verify-full&sslrootcert=/nonexistent.pem` gives an error naming `sslrootcert`, the path and "no such file", with no connection attempted.
- [ ] A directory as `sslrootcert` names the path and says it is a directory.
- [ ] A relative path's message shows the resolved path.
- [ ] `sslmode=disable&sslrootcert=/nonexistent.pem` connects.
- [ ] `not a url` and `mysql://…` give today's messages.

**Out of scope:**
- Invalid `sslmode` values (148).
- Client certificates beyond reading the files.
