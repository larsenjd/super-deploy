# 186: A migration whose scripts fire a trigger that reads an external schema can never be rehearsed, though the README implies it's supported

**Status:** ready-for-agent
**Category:** bug
**Severity:** medium
**Area:** privs
**Round:** 2

## What I did
Project with `managedSchema: "app"`, `externalSchemas: ["auth"]`, a deployed table
`notes (id ..., body text not null)`. Target `qa` has `auth.users`. Desired schema
adds:

```sql
create function notes_stamp() returns trigger
language plpgsql as $$
begin
  if exists (select 1 from auth.users where name = current_user) then
    new.body := new.body || ' (by known user)';
  end if;
  return new;
end
$$;

create trigger notes_stamp_trg before insert on notes for each row execute function notes_stamp();
```

```sh
pnpm exec super-deploy draft --name "notes trigger"
echo "insert into notes (body) values ('migration 11 ran');" > data-model/draft/post-migration.sql
pnpm exec super-deploy rehearse
```

## Expected
The README's "External schemas" bullet says routines run as their caller, "so it's
the application's roles that need these grants (and the deploy role too, if a
migration's scripts fire a trigger that uses them)", which reads as: grant the
deploy role access and it works.

## Actual
```
Error: data-model/draft/post-migration.sql:1: PostgreSQL refused it: relation "auth.users" does not exist.
```

Rehearsals have no `auth` schema, so the draft can't be rehearsed or finalized
whatever the targets have. The message doesn't say the failure happened in the
rehearsal (not on a target), or that rehearsals lack external schemas.

## Notes
- README "Permissions" > External schemas, and "Project settings" >
  `externalSchemas` ("nor reproduces them in rehearsals").
- I found no workaround: `alter table notes disable trigger notes_stamp_trg` around
  the insert is refused in `post-migration.sql` (`ALTER TABLE is not allowed in a
  post-migration script ... [deploy-time-statement]`), the trigger doesn't exist yet
  when `pre-migration.sql` runs, and `SET session_replication_role` is refused.
- Suggest: say plainly that a migration's scripts can't fire anything that reads an
  external schema, and make the rehearsal error mention that `auth` is an external
  schema rehearsals don't have.

### Triage, 2026-10-21

**Verification:** CONFIRMED. With `externalSchemas: ["auth"]`, the reporter's `notes_stamp` trigger in the desired schema and `insert into notes ...` in `post-migration.sql`, `rehearse` fails with `Error: data-model/draft/post-migration.sql:1: PostgreSQL refused it: relation "auth.users" does not exist.` The target `qa` has `auth.users` and the deploy role can read it, but the draft can never be rehearsed, finalized or deployed. Not run, but by the same cause: once such a trigger is deployed, every later migration whose scripts (or seed data) write to `notes` fails the same way, and so does the drift check's replay of the migration.

**Root cause:** rehearsals don't contain external schemas, by design (spec stories 45 and "Objects ... may reference only `pg_catalog`, except that PL/pgSQL bodies may reference declared external schemas"; README `externalSchemas`). A PL/pgSQL body that reads one passes the rules, so it loads, but fails as soon as it runs in a rehearsal. The README's "and the deploy role too, if a migration's scripts fire a trigger that uses them" (`packages/template/README.md:458-459`) promises something that can't work. The script-failure message (`SqlFileFailedError`, `rehearsal/replay.ts:289-305`) doesn't say the failure was in a rehearsal or mention external schemas; only desired-schema loading has an external-schema hint (`externalHint`, `rehearsal/throwaway.ts:157`).

**Intended?** The limitation is (rehearsals lack external schemas); the README sentence and the bare error aren't.

## Agent Brief

**Category:** bug
**Summary:** The README says plainly that a migration's scripts and seed data can't run anything that reads an external schema, and a rehearsal failing on an external schema says why.

**Current behavior:**
The README implies a migration's scripts may fire a trigger that reads an external schema if the deploy role has grants on it. Every rehearsal of such a migration fails with `relation "auth.users" does not exist`, with no hint that `auth` is an external schema rehearsals lack.

**Desired behavior:**
- The README's "External schemas" point drops "(and the deploy role too, if a migration's scripts fire a trigger that uses them)" and says instead: rehearsals have no external schemas, so a migration's scripts and seed data can't fire a trigger (or anything else) that reads one; such a trigger also blocks later scripts that write to its table. The `externalSchemas` setting's description points to it.
- When a pre-/post-migration script or seed data fails in a rehearsal with an undefined table, function, type or schema (SQLSTATE 42P01, 42883, 42704, 3F000) and the message names a declared external schema, the error adds that it failed in a rehearsal and that `"<schema>"` is an external schema rehearsals don't contain, so the script must not touch anything that reads it.
- Deployments on a real target get no such hint (the schema exists there, or the target lacks it, which is the DBA's job).

**Key interfaces:**
- `SqlFileFailedError` and its next-step text; the rehearsal path that raises it knows the config's `externalSchemas`.
- `externalSchemaExplanation`, the existing wording for the desired-schema case, to reuse.

**Acceptance criteria:**
- [ ] The reporter's project: `rehearse` fails with a message that names `auth` as an external schema rehearsals don't contain (API seam).
- [ ] A script failing on a missing table unrelated to external schemas gets no such hint.
- [ ] The README no longer says the deploy role's grants make this work, and states the limitation.

**Out of scope:**
- Making rehearsals contain external schemas (stub schemas, or a config of DDL for them): a feature for REFINEMENTS if wanted.
- Allowing scripts to disable triggers (`ALTER TABLE ... DISABLE TRIGGER`, `session_replication_role`).
- Checking external schemas on targets (round 1: 06, 31, 34).
