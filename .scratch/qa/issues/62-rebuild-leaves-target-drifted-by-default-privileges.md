# 62: rebuild reports success but leaves the target drifted when the deploy role has default privileges

**Status:** wontfix
**Category:** bug
**Severity:** medium
**Duplicate of:** 27
**Area:** disp

## What I did
Disposable target `sb2` (deploy role `disp_deploy`), migrations 1-5 deployed,
`status --target sb2` clean (exit 0). Someone sets default privileges for the
deploy role by hand:

```sql
set role disp_deploy;
alter default privileges in schema public grant select on tables to disp_extra;
```

Then:

```sh
pnpm exec super-deploy rebuild --target sb2 --to 5   # at a terminal, typed YES
pnpm exec super-deploy status --target sb2
```

## Expected
The README says "`rebuild` leaves the managed schema's grants exactly as the
migrations declare". So either rebuild clears/ignores the default privileges
while replaying, or it refuses up front ("default privileges for disp_deploy
in public would add grants: remove them first") without wiping anything.

## Actual
```
Rebuilt sb2 with 5 migrations: 00001-add-customers, 00002-add-orders, 00003-add-notes, 00004-add-tags, 00005-tag-color
```
then

```
Drift (the target differs from its recorded migrations):
  changed: table customers
  changed: table notes
  changed: table orders
  changed: table tags
Error: Target sb2 has drifted from its recorded migrations: table customers (changed), ... Deployments refuse until it matches them again
```

Every table created by the replay got `disp_extra=r/disp_deploy`. The freshly
rebuilt target can't take a deploy. Reproduced twice (on `sandbox` with
`--to 2` and on `sb2` with `--to 5`).

## Notes
The README does warn against `ALTER DEFAULT PRIVILEGES` for the deploy role,
but in the context of `deploy`. The point of `rebuild` is to get a clean
target back; it's the command a user would reach for after this mistake, and
it reports success. Default privileges set by *other* roles (e.g. `postgres`)
correctly have no effect.

### Triage, 2026-10-20

Closed as a duplicate of 27: its findings are folded into 27's brief.

**Verification:** CONFIRMED in the pseudo-terminal. On a disposable target where the deploy role has `alter default privileges in schema app grant select on tables to extra`, `rebuild --to 1` printed `Rebuilt`, then `status` exited 1 because every table had the extra grant. The wipe keeps default privileges on purpose, and nothing checks the result before COMMIT.
