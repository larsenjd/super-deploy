## Agent Brief

**Category:** enhancement
**Summary:** When the managed schema doesn't exist, adoption's refusal lists the target's schemas, and says how to handle one whose name isn't lowercase.

**Current behavior:**
`Cannot adopt target qa: its managed schema "shpo" does not exist (check managedSchema in super-deploy.config.ts). Nothing was written`. A mixed-case schema can't be configured, and the user gets no hint why the lowercase spelling isn't found.

**Desired behavior:**
- The refusal lists the target's non-system schemas, leaving out `pg_*`, `information_schema` and the history schema, e.g. `the target has schemas "MyApp", shop`. With none, it says the target has no schemas besides the system ones.
- If one of them matches `managedSchema` ignoring case, the refusal says that `managedSchema` must be lowercase and the schema must be renamed first, e.g. `ALTER SCHEMA "MyApp" RENAME TO myapp`, along with the application's references to it.
- The README's "Adopting an existing database" says the same about non-lowercase schema names.
- Nothing is written, as today.

**Key interfaces:**
- The adoption command's managed-schema check and `AdoptConflictError`'s reasons.
- If 123 is decided as a refusal, its list of other schemas can share this query.

**Acceptance criteria:**
- [ ] API seam: `managedSchema: "shpo"` on a target with schemas `shop` and `"MyApp"` refuses, naming both.
- [ ] `managedSchema: "myapp"` on that target names `"MyApp"` and the rename.
- [ ] The project and the target are unchanged after either refusal.
- [ ] README updated.

**Out of scope:**
- Allowing mixed-case `managedSchema` values.
- Empty managed schemas (123).
