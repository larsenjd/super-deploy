## Brief (ready-for-human)

**Category:** enhancement
**Summary:** A rehearsal mismatch should only say "run draft again" when re-drafting can help.

**Current behavior:**
Every mismatch says "The rehearsal does not match the desired schema; run draft again", followed by one difference in catalog notation and "(and N more)". When the desired schema hasn't changed since the draft was generated, re-drafting regenerates the same schema change and the error repeats.

**Desired behavior (once decided):**
- When the desired schema changed since the draft, keep "run draft again".
- When it hasn't, say the scripts (pre-migration, post-migration, seed data) or a hand edit cause the mismatch, and point to the README's renaming section for constraint names.
- If a schema-change hash is stored, a hand-edited `schema-change.sql` is named as such.

**Key interfaces:**
- The rehearsal mismatch error raised by `requireSameStructure`.
- The draft's metadata (`draft.json`), which has `desiredSchemaHash`, and may gain a schema-change hash.

**Acceptance criteria (once decided):**
- [ ] A rename in the pre-migration script that misses the constraint rename gives a message that doesn't say "run draft again".
- [ ] A desired-schema change made after the draft still says "run draft again".
- [ ] A hand-edited `schema-change.sql` is reported as edited (if the hash is added).

**Out of scope:**
- Listing every difference instead of "(and N more)" (02).
- The comment comparison bug (01).
- `draft` warning statically about renamed NOT NULL columns.

**Why not delegated:** message wording, plus whether to add a new hash to the draft metadata format.
**Decision needed:**
- Branch the message on the stored desired-schema hash, and add a schema-change hash so hand edits are named (recommended).
- Branch only on the desired-schema hash; no metadata change.

### Decided, 2026-10-21

The maintainer chose: **two hashes.** `draft.json` keeps `desiredSchemaHash` and gains a hash of the `schema-change.sql` that `draft` wrote.

- On a rehearsal mismatch:
  - desired schema changed since `draft`: "run draft again" (as today);
  - desired schema unchanged, `schema-change.sql` edited by hand: say so, and say the hand edit doesn't produce the desired schema;
  - neither changed: say the scripts or seed data cause it (pre-migration, post-migration, seed data), and point to the README's renaming section for constraint names.
- A draft written before this change (no schema-change hash) is treated as not hand-edited.

**Acceptance criteria:** the brief's three, with the hash added.
