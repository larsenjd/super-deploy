# 67: A target holding a deployed draft is described as "recorded history doesn't match the project's migrations"

**Status:** ready-for-agent
**Category:** enhancement
**Severity:** low
**Area:** disp

## What I did
Disposable target `sandbox` at migration 3; `deploy-draft --target sandbox`
(typed YES). Then:

```sh
pnpm exec super-deploy status --target sandbox
pnpm exec super-deploy mark --target sandbox
```

## Expected
Messages that say the target holds a draft. Its recorded migrations 1-3 do
match the project's.

## Actual
`status`:
```
Target sandbox (disposable): 3 migrations recorded, 0 pending
Deploy would refuse:
  the target holds draft add-tags (deployed by attempt #3 on top of 00003-add-notes, without seed data), not a finalized migration: reset it with rebuild --to 3
Drift: not checked (the recorded history doesn't match the project's migrations)
```
`mark`:
```
Error: Target sandbox's recorded migrations don't match the project's: the target holds draft add-tags ...
```

The first clause of both is misleading; the second is right. Also, hand-made
changes on such a target are never checked for drift, so `status` can't tell
you what else is on it.

`deploy` gets this right ("failed the deploy pre-flight checks: the target
holds draft ...").

## Agent Brief

**Category:** enhancement
**Summary:** `status` and `mark` describe a target holding a deployed draft as such, not as a history mismatch.

**Current behavior:**
A disposable target that holds a deployed draft has recorded migrations that match the project's. The pre-flight checks report it with reason `draft`. But `status` says "Drift: not checked (the recorded history doesn't match the project's migrations)". `mark` opens its error with "Target X's recorded migrations don't match the project's:" before the correct clause about the draft. `deploy` already gets it right ("failed the deploy pre-flight checks: the target holds draft ...").

**Desired behavior:**
When every history mismatch has reason `draft`:
- `status` says "Drift: not checked (the target holds deployed draft <name>; rebuild resets it)" or similar.
- `mark`'s refusal leads with the draft ("Target X holds deployed draft <name> ...; reset it with rebuild --to N"), without claiming the recorded migrations don't match.

When there is a real history mismatch, alone or alongside a draft, the current wording stays.

**Key interfaces:**
- The pre-flight history reasons (`reason: "draft"` versus the others).
- `status`'s rendering of the "Drift: not checked" line.
- The error `mark` throws for a history mismatch (keep its `code`, change the message for the draft-only case).

**Acceptance criteria:**
- [ ] CLI seam: after `deploy-draft` (pseudo-terminal), `status --target X` prints a "Drift: not checked" line that names the deployed draft and doesn't say the recorded history doesn't match.
- [ ] Pseudo-terminal: `mark --target X` on that target refuses with a message that leads with the deployed draft and doesn't contain "recorded migrations don't match".
- [ ] A target whose recorded history really differs (e.g. a changed content hash) prints exactly the current wording.

**Out of scope:**
- Checking drift on a target holding a draft (by design, ADR-0005).
- `deploy`'s message (already right).
