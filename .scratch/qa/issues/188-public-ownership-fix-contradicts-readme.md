## What I did
```sql

create database qa2_privs_pub;
grant create on database qa2_privs_pub to qa2_privs_deploy;
```

New project with the default `managedSchema` (`public`), one table, finalized; target
`pub: { adapter: postgresTarget({ env: "PUB_DATABASE_URL" }) }` with
`PUB_DATABASE_URL=postgres://qa2_privs_deploy:pw@localhost:54818/qa2_privs_pub`.

```
$ pnpm exec super-deploy status --target pub
Target pub: 0 migrations recorded, 1 pending
Deploy would refuse:
  schema public is owned by pg_database_owner, whose privileges the deploy role doesn't have (fix: ALTER SCHEMA public OWNER TO qa2_privs_deploy)
```

## Expected
The fix the README gives: "For `public`, which `pg_database_owner` owns, deploy as
the database's owner", i.e. `ALTER DATABASE qa2_privs_pub OWNER TO qa2_privs_deploy`.

## Actual
The message suggests taking `public` away from `pg_database_owner`, which PostgreSQL
15+ sets up on purpose. Both fixes work (I used `alter database ... owner to
qa2_privs_deploy`, then `deploy` succeeded), but the README and the tool point a DBA
in different directions.

## Notes
Suggest special-casing `public` owned by `pg_database_owner` in the message:
`(fix: ALTER DATABASE <db> OWNER TO <deploy role>, or ALTER SCHEMA public OWNER TO
<deploy role>)`. The message also doesn't say the fix must be run by a superuser or
the current owner.
