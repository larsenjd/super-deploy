# 143: An interrupted deploy doesn't say whether the target changed

**Status:** wontfix
**Category:** enhancement
**Severity:** low
**Duplicate of:** 110
**Area:** fail

## What I did
Target `qa` with migration 3 pending. Another session holds a lock on `app.customers`, so the deploy waits at `ALTER TABLE … SET NOT NULL`. Ctrl+C, either from the interactive menu in a pty or by `kill -INT -<pgid>`. Same with SIGTERM and SIGHUP:

```sh
setsid pnpm exec super-deploy deploy --target qa > out 2> err & P=$!
sleep 4; kill -INT -- -$P; wait $P; echo "exit=$?"; cat out err
pnpm exec super-deploy status --target qa
```

## Expected
A last line saying what happened to the target, like a failed deploy's message: "The deployment rolled back: target qa is unchanged, still at migration 00002-add-orders."

## Actual
```
exit=130
Interrupted by SIGINT: cleaning up before exiting (interrupt again to exit at once)
```
Nothing follows. Only `status` shows `#7 deploy abandoned migration 3 …: Interrupted (SIGINT)` and the migration still pending. The same holds for SIGTERM (exit 143) and SIGHUP (exit 129).

## Notes
The exit codes are right. The open question for someone who just pressed Ctrl+C on a production deploy is "did any of it commit?", and the CLI could answer that right away, as it does for a failed deploy.
