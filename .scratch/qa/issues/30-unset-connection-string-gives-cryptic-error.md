# 30: A target whose connection-string variable is unset fails with "ENOTFOUND base" or "reading 'charAt'"

**Status:** wontfix
**Category:** bug
**Severity:** low
**Duplicate of:** 04
**Area:** adopt

## What I did
Target configured as the README suggests (connection string from an environment variable), then a command run in a shell where the variable isn't set:

```ts
shop: { adapter: postgresTarget({ connectionString: process.env.SHOP_DATABASE_URL ?? "" }) },
```
```sh
env -u SHOP_DATABASE_URL pnpm exec super-deploy status --target shop
```

and with `connectionString: process.env.GEN_DATABASE_URL as string` (so `undefined`):

```sh
env -u GEN_DATABASE_URL pnpm exec super-deploy status --target gen
```

## Expected
Something like `Target shop has an empty connection string; check the environment variable super-deploy.config.ts reads it from`.

## Actual
```
Error: The deployment adapter of target shop failed to connect: getaddrinfo ENOTFOUND base
```
```
Error: The deployment adapter of target gen failed to connect: Cannot read properties of undefined (reading 'charAt')
```

Neither says the connection string is missing. The second one leaks an internal JavaScript error.

## Notes
`postgresTarget` could reject an empty or undefined `connectionString` when the config loads, or when a command first uses that target (other targets, like `dev`, should keep working without the variable, as they do today).
