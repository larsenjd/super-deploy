# 43: An unreachable target host hangs for over 2 minutes with no output

**Status:** ready-for-agent
**Category:** enhancement
**Severity:** low
**Area:** fail

## What I did
```sh
FAIL_DOWN_URL="postgres://u:p@10.255.255.1:5432/x" pnpm exec super-deploy status --target down
FAIL_DOWN_URL="postgres://u:p@10.255.255.1:5432/x" pnpm exec super-deploy deploy --target down
```
(a non-routable address, as with a firewalled host or a wrong VPN)

## Expected
A connect timeout of a few seconds (or a configurable one), or at least a "connecting to 10.255.255.1:5432..." line so the user knows what it's waiting for.

## Actual
Nothing is printed for 136 s (both `status` and `deploy`, 136.2 s and 136.3 s), then:
```
Error: The deployment adapter of target down failed to connect: connect ETIMEDOUT 10.255.255.1:5432
```

## Notes
`TargetConfig` has `lockTimeout` and `statementTimeout` but no connect timeout. A user could add `connect_timeout=5` to the connection string if node-postgres honours it, but nothing documents that.

### Triage, 2026-10-20

**Verification:** CONFIRMED. A target at `10.255.255.1` printed nothing, then failed after about 134 s with `connect ETIMEDOUT`. The reporter's suggested workaround doesn't work: adding `?connect_timeout=2` to the URL, or setting `PGCONNECT_TIMEOUT=2`, made no difference (about 136 s). Root cause: the node-postgres adapter's connect (`adapters/node-postgres.ts`, `connectSession`) never sets `connectionTimeoutMillis`, which is the only thing pure-JS `pg` arms its connect timer from. `connect_timeout` only feeds the libpq connection string. Also, a SIGTERM 8 s in didn't stop the CLI until the TCP connect gave up, because the connect ignores the interruption signal (a second Ctrl+C does exit).

## Agent Brief

**Category:** enhancement
**Summary:** Connecting to a target times out after 10 s by default, configurable per target with `connectTimeout`, and an interruption stops a pending connect.

**Current behavior:**
Connecting to an unreachable host waits for the operating system's TCP timeout (over two minutes) with no output. There is no connect timeout option, and `connect_timeout` in the connection string is ignored by node-postgres. A Ctrl+C or SIGTERM during the connect doesn't take effect until the connect fails.

**Desired behavior:**
- Target connections time out after 10 s by default. The error says what timed out and how to change it, e.g. `The deployment adapter of target down failed to connect: no answer from 10.255.255.1:5432 within 10s (connectTimeout in super-deploy.config.ts)`.
- A target accepts an optional `connectTimeout`, in the same duration format and validation as `lockTimeout` (e.g. `"500ms"`, `"5s"`, `"2min"`).
- An interruption (the project's abort signal) during a connect abandons it promptly, and the command exits with the usual interruption code.
- The embedded adapter's local connections behave as today, or use the same default if that is simpler. Either way, it must not slow down normal starts.

**Key interfaces:**
- The target config type (alongside `lockTimeout` and `statementTimeout`): new optional `connectTimeout`, with config validation and the same duration parser.
- `postgresTarget` / the node-postgres connect path: passes the timeout to node-postgres (`connectionTimeoutMillis`) and honours the abort signal.

**Acceptance criteria:**
- [ ] `status` against a non-routable address fails within about the configured `connectTimeout` (e.g. `"1s"` in a test) with a message naming the host, the timeout and the setting (API or CLI seam; use a short timeout in tests).
- [ ] Without `connectTimeout`, the default is 10 s (unit-level check of the resolved config is enough).
- [ ] An invalid `connectTimeout` (e.g. `"5 seconds"`) is refused at config load with the same style of message as `lockTimeout`.
- [ ] Signalling the CLI during a pending connect exits with the interruption code within about a second (CLI seam).

**Out of scope:**
- Honouring `connect_timeout` from the URL.
- Retrying connections.
- Documenting the option in the README beyond what issue 03's config reference covers.
