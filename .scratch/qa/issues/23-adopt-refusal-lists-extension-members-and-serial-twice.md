# 23: Adoption refusal lists every member of an extension, and calls a serial column a "standalone sequence" twice

**Status:** ready-for-agent
**Category:** enhancement
**Severity:** low
**Area:** adopt

## What I did
```sql
-- as postgres in qa_adopt_unsup
create schema legacy authorization adopt_deployer;
create extension citext schema legacy;
set role adopt_deployer;
create table legacy.items (id serial primary key, name text not null);
create aggregate legacy.text_concat(text) (sfunc = textcat, stype = text, initcond = '');
```

Project with `managedSchema: "legacy"` and target `legacy`, then `pnpm exec super-deploy init --adopt legacy </dev/null`.

## Expected
- One entry for the extension: "extension citext: Extensions other than plpgsql are not supported".
- One entry for the serial column, saying serial isn't supported and to use an identity column.

## Actual
`Target legacy has 49 things V1 doesn't support:`. About 36 of those come from the one extension: `function max(citext)`, `function min(citext)`, `type citext`, 27 `operator ...(citext,...)` entries, 3 operator classes, 3 operator families, then `extension citext`. The entries the user can act on are buried among them.

The serial column becomes two entries, neither of which mentions the column:

```
  CREATE SEQUENCE "legacy"."items_id_seq" AS integer INCREMENT BY 1 ...
    unsupported-object: Standalone sequences are not supported in V1: use an identity column (`bigint generated always as identity`)
  ALTER SEQUENCE "legacy"."items_id_seq" OWNED BY "legacy"."items"."id"
    desired-schema-statement: ALTER SEQUENCE is not allowed in the desired schema
```

`items_id_seq` isn't standalone; it belongs to the serial column `items.id`.

## Notes
Suggestion: group objects that belong to an extension (`pg_depend` deptype `e`) under the extension, and report a sequence owned by a column as "serial column items.id".

## Agent Brief

**Category:** enhancement
**Summary:** Adoption refusals list an extension once and a serial column once, instead of every member object and the column's sequence twice.

**Current behavior:**
When `init --adopt` refuses a target, the list of unsupported things has one entry per catalog object. An extension adds an entry for each of its member functions, types, operators, operator classes and operator families, and then one for the extension itself. A `serial` column adds two entries: its sequence ("Standalone sequences are not supported in V1") and the sequence's `OWNED BY` statement ("ALTER SEQUENCE is not allowed in the desired schema"). Neither entry names the column.

**Desired behavior:**
- Objects that belong to an extension (a `pg_depend` entry with `deptype = 'e'`) are left out of the refusal. The extension keeps its single entry with the existing reason ("Extensions other than plpgsql are not supported").
- A sequence owned by a table column (`deptype = 'a'`), together with its `OWNED BY`, is reported as one entry naming the column, e.g. `serial column legacy.items.id: serial columns are not supported; use an identity column (bigint generated always as identity)`.
- A truly standalone sequence (owned by no column) keeps today's "Standalone sequences" entry.
- The entry count in "Target X has N things V1 doesn't support" counts the entries after grouping.

**Key interfaces:**
- `AdoptUnsupportedError` and its list of unsupported objects: fewer, grouped entries; the shape stays as it is.
- The catalog facts that adoption reads from the target (`catalogFacts` and the "other objects" facts): either filter extension members there, or have adoption filter them using `pg_depend`.
- The adoption step that turns the differ's statements and the catalog's leftover objects into refusal entries.

**Acceptance criteria:**
- [ ] Adopting a managed schema that holds `citext` gives exactly one entry for the extension and none for its functions, types, operators, operator classes or families (API seam, `init --adopt` / `adopt`).
- [ ] Adopting a table with a `serial` column gives exactly one entry, which names the column and suggests an identity column. No separate `CREATE SEQUENCE` or `ALTER SEQUENCE ... OWNED BY` entries.
- [ ] A standalone `create sequence` still gives the "Standalone sequences" entry.
- [ ] The count in the refusal's first line matches the number of entries listed.

**Out of scope:**
- Supporting extensions or serial columns (both stay refused by design).
- The refusal's closing advice ("change the target first"); that is issue 35.
