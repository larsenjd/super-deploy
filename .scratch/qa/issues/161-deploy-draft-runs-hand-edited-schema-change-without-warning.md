## What I did
Project at migration 3 (`managedSchema: "app"`); a disposable shared-server target `qa` at migration 3.
```sh
# desired schema: add a column to customers
pnpm exec super-deploy draft --name "customer names"
echo 'create table app.sneaky(x int);' >> data-model/draft/schema-change.sql   # a hand edit
pnpm exec super-deploy deploy-draft --target qa    # in a terminal, type YES
pnpm exec super-deploy rehearse
```

## Expected
deploy-draft warns, or refuses, that `schema-change.sql` was edited by hand since `draft` generated it. `draft.json` holds the generated schema change's hash, and `rehearse` uses it to say so. Round 2 says "deploy-draft warns about a stale draft", and it does refuse when the desired schema changed after `draft`.

## Actual
The confirmation lists `data-model/draft/schema-change.sql` as usual, with no warning. YES deploys it:
```
Deployed draft customer-names to qa on top of 00003-add-notes, without seed data
```
`app.sneaky` now exists on qa. Meanwhile `rehearse` says:
```
Error: The rehearsal does not match the desired schema: data-model/draft/schema-change.sql was edited by hand since draft generated it, and the edited schema change doesn't produce the desired schema (run draft again to regenerate it) (3 differences, listed above)
```

## Notes
For comparison, after changing the desired schema without re-running draft, deploy-draft refuses before asking: `Error: The desired schema has changed since draft customer-names was generated: run draft again`. The README's deploy-draft bullet mentions neither check. Its "run without a rehearsal first" makes the hand-edit check the only safeguard here.

## Brief (ready-for-human)

**Category:** bug
**Summary:** `deploy-draft` should not run a hand-edited `schema-change.sql` without saying so.

**Current behavior:**
`deploy-draft` refuses a draft whose desired schema changed since `draft`, but deploys a hand-edited schema change without a word. It runs without a rehearsal first, so nothing else catches the edit before it reaches the target.

**Desired behavior (once decided):**
Before the YES question, `deploy-draft` compares `schema-change.sql` with `draft.json`'s `schemaChangeHash`. If they differ, it refuses or warns, as decided below. A draft written before the hash existed counts as not edited, as `rehearse` treats it. A Recovery draft is unaffected, since its schema change is the migration's own and has its own check (`RecoverySchemaChangeEditedError`).

**Key interfaces:**
- `deployDraft`'s pre-question check, next to `UndraftedChangesError`.
- `DraftMetadata.schemaChangeHash` and the comparison `rehearse` already makes.
- The README's `deploy-draft` bullet: name the checks it makes before asking.

**Acceptance criteria (once decided):**
- [ ] Pseudo-terminal: with a hand-edited `schema-change.sql`, `deploy-draft` refuses before any YES prompt (option 1) or shows a warning line in the confirmation (option 2), naming the file and `draft` as the way to regenerate it.
- [ ] An unedited draft deploys as today, and a draft without `schemaChangeHash` is treated as unedited.
- [ ] The README's `deploy-draft` bullet says what it checks before asking.

**Out of scope:**
- `finalize` accepting a hand-edited schema change (108). Decide both together, so `deploy-draft` and `finalize` follow one policy.
- The rehearsal mismatch wording (17, resolved).

**Why not delegated:** whether a hand-edited schema change is ever acceptable is a policy question. `rehearse` accepts an edit that produces the desired schema, while the README and the file's header say "never edit it".
**Decision needed:**
- **(recommended)** Refuse before asking, with a typed error like `UndraftedChangesError` ("schema-change.sql was edited by hand since draft generated it: run draft again"). `deploy-draft` has no rehearsal, so the hash is its only safeguard. Make `finalize` refuse too (108).
- Warn in the confirmation ("schema-change.sql was edited by hand since draft generated it and hasn't been rehearsed") and go ahead on YES.
- Allow the edit when a rehearsal passed since then (would need recording that a rehearsal passed).
